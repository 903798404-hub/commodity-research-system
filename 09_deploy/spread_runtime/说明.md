# Spread Production Runtime Wiring

本目录是 `spread-production-runtime-wiring` 的部署源码，服务仍为完整 `spread-dashboard`。Runtime Manifest 是 `02_configs/runtime_contracts/spread-production-runtime.json`。登记和源码实现不等于容器验收或生产批准。

## 候选与生产身份

从精确 Commit/Tree 的干净 Git 源码构建 digest-pinned Python 镜像；`RELEASE.json` 的 application 是项目 ID，OCI service 是 `spread-dashboard`。镜像不包含 `.git`、候选 fixture、私钥或生产数据。使用数值非 root 用户和只读 root filesystem。业务容器不挂 Docker socket，不签发授权。

执行身份必须显式选择。容器使用受保护宿主注入的只读 grant，同时验证 RELEASE、manifest、实际镜像和实例配置。Git CLI 要求显式 Git identity 和 Approved Commit/Tree，不接受 repository_root 或 runtime marker 单独授权。任何身份失败均退出，不自动回退到开发模式。

## 部署来源和存储

所有 Compose 命令以精确候选源码根作为 `--project-directory`，使用本目录 `compose.yml`；不能因为路径名相同就把另一份 Compose 当作实际部署源。生产 release 记录 source/rendered Compose SHA、实际 mounts、环境、Image ID 和宿主授权。通过候选验收的 Image ID 直接提升，正式切换禁止 build。

`SPREAD_IDENTITY_ROOT` 是受保护正式 identity 根。数据、Weather、历史 runtime、snapshot consumer、result 和 CNF 根为只读；outputs/logs 为独立可写目录。各来源必须来自批准的 production allocation，不能指向开发 worktree、旧 PM worktree、Preview 或候选临时数据。

`SPREAD_SNAPSHOT_ROOT` 同时以只读 consumer `/runtime/import-profit/snapshots` 和可写 capture alias `/runtime/capture-snapshots` 挂载。生产预检及显式 capture 必须确认二者实际为同一目录；CLI 只能写入 grant 授权的 alias。候选使用独立只读合成 snapshot 和独立空的临时可写 alias，不能把 fixture 挂成可写来模拟生产。

页面固定 `STRICT_RUNTIME` / `FORMAL`，不启用 CNF save，不传历史 business_date 或页面写入授权变量。Tankan 仍使用 `TANKAN_SECRET_FILE` 所指文件，通过 Compose secret 注入 `/run/secrets/tankan.env`，不创造包含秘密的新环境变量。初始化不读取该秘密、不访问网络、不 capture。

## 验收

13 个明确登记的合成输入仅用于候选验证：其 Git blob SHA 和目标只读路径绑定在 manifest 中，由通用引擎放入受保护的临时 mount。不得复制为生产 runtime，也不得把这些 synthetic snapshot 当作真实 AM/PM temporal acceptance。

只读 preflight 初始化真实 CLI identity、Domestic Spread reader、Soybean STRICT_RUNTIME 页面和 immutable snapshot consumer。生产预检只读取已有 SEALED；正式 AM 不是部署前置条件，只有 PM 时验证 PM，合法空 Snapshot store 报告 `NOT_YET_AVAILABLE`，不要求补采。已有 release 不完整、环境不符、身份或内容校验失败仍然失败，不能作为空 store 忽略。候选读取明确的 synthetic SEALED。缺少实际 runtime、身份或依赖必须失败。有效的投产前空 AM/PM 状态不等于已验证真实 AM/PM capture 或结果批次展示。

代码 closure 前必须取得实际隔离 Linux image 的全部正反向 Deployability probe 和签名 candidate record，再按项目 Completion 和独立 integration 验收。Windows 上的解析或 Python tests 不能替代容器 PASS。当前目录不能自我签发 Production Approval。

## 激活边界

不新增 cron、Scheduled Task、自动 AM/PM capture、FULL DAILY/Wrapper/Provider Preflight/Daily Summary 接入或 Notification activation。只读部署 smoke 不执行 capture，也不修改旧 SEALED。未来显式执行 capture 时必须指定日期/session、request/calendar、正式 identity 和 capture alias，并通过现有 secret-file 与数据合同。

`AM_PM_AUTO_EXECUTION=NO`；`INTRADAY_FULL_DAILY_DEPENDENCY=NONE`；`NOTIFICATION_AUTO_EXECUTION=NO`。`REAL_AM_TEMPORAL_ACCEPTANCE=DEFERRED`；`REAL_PM_TEMPORAL_ACCEPTANCE=DEFERRED`；temporal acceptance 不阻塞部署。
