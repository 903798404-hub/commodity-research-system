# 主机执行授权工具

`host_authorization.py` 是生产执行身份合同的主机侧工具。它从 Docker
读取实际容器、镜像、配置、挂载和 RELEASE 数据，校验这些观测是否符合受保护
的主机策略，之后才签发短时效 Ed25519 grant。签发入口不接受调用方提供的
`observed` 字典。

生产 grant 与 candidate validation grant 使用不同的 trust domain。候选验证只
允许临时 runtime root 和候选 artifact。grant 以 `O_EXCL` 独占创建，已有 grant
绝不覆盖；私钥保持 root-owned、0600。Docker socket、host namespace、特权容器、
设备、额外 capability、可写 rootfs 和 root 用户都会被拒绝。

本工具不启动或部署业务容器；部署编排器只能在 grant 密封并以只读方式注入后，
启动已经完成实际检查的新容器。

本阶段只完成主机观测、纯校验和签发接口，尚未完成真实 Linux Docker candidate
验证。默认 trust 配置为空，因此默认拒绝签发；本目录不代表已具备生产可用授权。
程序读取 Docker 和受保护策略，写入一次性 grant；人工不得直接修改已签发 grant。
正式生产数据、secret、私钥和持久业务 volume 不得放入本目录；candidate 临时
文件只在候选生命周期内存在。

本源码目录不是临时目录。人工可通过项目治理维护代码和 Schema；程序不在本目录生成运行产物。

## 调用与兼容

[RuntimeContext](../../03_src/agri_research_agent/shared/runtime_context.py) 显式接受
[GitExecutionRequest 或 OCIExecutionRequest](../../03_src/agri_research_agent/shared/production_identity.py)，
不探测后自动切换类型。Git 路径必须属于当前实际执行源码、正常 checkout、clean、完整 Approved
Commit/Tree 一致；空 `.git`、linked worktree、其他 checkout、隐藏索引变更或 Git 身份重定向均拒绝。
Approved 输入由可信调用链提供，不能从 runtime marker 推导。

`FORMAL_READONLY` 保持只读。`PRODUCTION_WRITE` 和新的 `CANDIDATE_VALIDATION` 每次写入前
都重新验证材料；候选使用 `candidate-validation` 标记及独立签名域。module、runtime ID、marker SHA、
resolved path 和签名 writable roots 共同限制写入。返回的验证对象不能作为长期授权缓存。
FULL DAILY trusted checkout/Wrapper 保持原有更强校验，不要求立即迁移到本库。

`artifact_origin=candidate` 与 `role=production` 可以同时成立；正式批准后可以提升同一个 Image ID。
artifact 来源、实际部署角色和写权限不是同一个字段，历史镜像 deployment label 不能授予权限。

## 宿主策略与执行顺序

宿主策略使用严格的 `host-runtime-policy/1`。精确字段由 `validate_policy` 限定：身份字段及
Approved Commit/Tree、Image ID、artifact service/RELEASE application、source/runtime 根、manifest
路径与 SHA、marker/RELEASE/实际配置 SHA、实际 mounts、按序 Compose `[{path, sha256}]`、真实
project directory、受保护 env 文件、rendered Compose SHA、grant 容器目录与 candidate host root。
这些是实例数据，不写入业务源码 runtime manifest；生产角色的 candidate host root 必须为空。

控制面先创建未启动的容器，设置随机 32 位 hex hostname nonce，再以受保护审批策略绑定完整实例。
签发器只处理 `created` 状态，内部实际 inspect、读取容器文件并验证：

1. OCI revision/tree/service/release label、不可变 Image ID、原始 RELEASE 字节和 Approved 身份；
2. 数字非 root UID、只读 rootfs、cap_drop ALL、no-new-privileges、命名空间和设备边界；
3. 真实 Compose 来源标签、按序 source SHA，重新渲染后逐项比较实际 image/entrypoint/Cmd/env/mount；
4. 容器内 manifest、marker 和公开信任锚原始字节，以及 manifest roots/mount 权限；
5. 真实 host mount source；拒绝控制 socket/device、代码覆盖或候选目录外的挂载；
6. 私钥的公钥必须在当前镜像信任配置中属于请求角色且未撤销；
7. 签名前再读实例，必须仍是同一个未启动容器。

当前授权版本仅接受显式 bind mount；其他类型保持拒绝，不静默近似。grant 目录为 root `0755`，
只读注入容器，grant 文件为 `0444`；private key 和审批策略为 root `0600`。祖先不可被其他用户
改写；候选临时根可经过 root sticky `/tmp` 祖先，但临时根本身必须由 root 控制。
私钥不得进入镜像或任何业务挂载。容器密封 grant 后的启动、失败清理和恢复由部署控制面负责。
授权最长一小时；过期、证据缺失或身份变化立即拒绝后续写入，不自动续期。

## 信任与测试边界

[公开信任配置](../../02_configs/production_runtime_trust.json) 初始为空。公钥启用必须作为受审查的
独立源码变更进入候选镜像；私钥只在获准宿主保存。候选与生产密钥不可复用，也不能通过环境变量
替换信任锚。[机器 grant Schema](production_authorization.schema.json) 使用 `production-execution-grant/1`。
Ed25519 签名覆盖排序 key、无额外空白、UTF-8 的 payload，固定版本及算法必须精确匹配。

签名绑定 Approved/RELEASE Commit/Tree、Image ID、RELEASE/manifest/marker SHA、实际配置、
rendered Compose、mount identity、container ID、nonce、角色、roots、grant ID 和时效。
容器库不能独立向 Docker 查询 Image ID；这一事实来自宿主真实观测与签名，容器内再验证不可变材料。
单元测试模拟 OS/Docker transport，但真正执行哈希、签名、Schema 和拒绝条件，不能代替真实容器门禁。
本工具不捕获业务数据、不通知、不调度、不提升 Approved Production。
