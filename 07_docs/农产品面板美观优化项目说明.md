# 农产品面板美观优化项目说明

**项目标识：** `agri-dashboard-visual-refresh`

**当前状态：** 页面与视觉契约已定义，等待本地 UI 开发。

**项目归属：** `spread-dashboard`。主要入口为 `05_apps/streamlit_app.py`，首页实现位置为 `05_apps/home.py`。

## 研究目标

在不改变业务事实、数据口径和应用边界的前提下，将现有主看板统一为专业、清晰且可扩展的农产品研究工作台。首页名称固定为“农产品研究工作台”，服务于研究人员快速进入模块、识别数据更新状态和处理需要关注事项。

## 本期范围

- 定义主工作台首页、侧边栏与模块入口的信息架构。
- 定义首页状态语义、异常提示边界和外部应用降级规则。
- 定义全站共享视觉变量与后续共享展示组件的职责边界。
- 后续本地 UI 开发仅限 `05_apps/` 内的展示代码；页面应复用现有数据读取、状态文件和路由。
- 桌面端优先，同时支持普通笔记本与窄屏下的自然换行和自动列数调整。

页面结构、状态语义、视觉变量和验收要求以[农产品研究工作台页面契约.md](农产品研究工作台页面契约.md)为唯一实施依据。

## 明确不做

- 不改变价差采集、计算、状态写入或 AKShare 更新流程。
- 不改变基差和一口价人工 Excel 录入、导入或展示口径。
- 不改变 USDA NASS、美豆周度、外资席位的更新流程、数据源、唯一键、Parquet Schema 或业务公式。
- 不新增容器，不改 Docker、Compose、端口、生产挂载、cron 或服务器配置。
- 不复制、合并、解析或重建 USDA 与 Oil World 的独立应用及其数据；主工作台只保留外部入口和状态展示。
- 首页不加载大量历史图表、明细数据或错误堆栈，不重新计算数据，也不触发更新任务。
- 不开发“最近访问”“自定义首页”，不保留对应的占位卡片、不可用按钮或误导性入口。

## 数据与展示边界

首页只读取现有可信文件、已有状态文件或现有外部地址配置，展示摘要而不生成新的业务结果。

| 模块 | 已有稳定输入 | 首页展示边界 |
|---|---|---|
| 市场价格 | `01_data/historical_spread_database.parquet`、`01_data/update_status.json` | 展示自动更新摘要和进入价差动态页面的入口。 |
| 国内现货 | `01_data/database/basis/basis_quotes.parquet` | 展示人工维护状态和最近业务日期；不得称为实时或自动更新。 |
| 美豆周度跟踪 | `01_data/processed/soybean_crop_progress/`、`01_data/update_status/soybean_crop_progress.json` | 展示周度更新语义和进入美豆种植生长页面的入口。 |
| 外资与重点席位 | `01_data/database/foreign_seats/foreign_seat_positions.parquet`、`01_data/foreign_seats_update_status.json` | 仅作为研究工具或数据状态项；已知部分失败时必须如实显示。 |
| USDA / Oil World | `USDA_DASHBOARD_URL`、`OIL_WORLD_DASHBOARD_URL` | 只展示独立应用入口与可用性，不读取或复制其业务数据。 |

本轮不扩写[数据字典](data_dictionary.md)。所有既有 Schema、主键、业务公式和数据质量规则保持原样。

## 页面与应用契约

- 六个固定首页入口为：市场价格、国内现货、美豆周度跟踪、USDA 供需平衡、Oil World 供需平衡、运行监控。
- 外资与重点席位不占用首页核心卡片位置，归入侧边栏“研究工具”或数据状态区域。
- 内部入口继续使用现有页面状态和路由；不得修改路由名称或访问路径。
- USDA 和 Oil World 必须继续通过环境变量解析地址，不得硬编码生产 IP。
- 共享组件只负责展示，不得写数据、执行任务、修改路由或保存个人配置。

## 运行与部署边界

本项目不改变 `spread-dashboard` 的容器归属。运行数据继续由宿主机挂载到容器内的 `/app/01_data`、`/app/06_outputs` 和 `/app/10_logs`，美观优化不得改变这些路径或访问方式。

本轮已确认的服务器审计发现：当前未找到 `production_baseline.json`，也未找到现存的 `release.json`、`candidate_result.json`、`deployment_plan.json` 或 `deployment_result.json`。该缺口不阻断本地文档和 UI 开发；但首次正式部署前，必须单独完成真实生产基线重建与密封，不能凭本项目文档补造或推断发布事实。

## 后续测试与验收

后续 UI 实现至少应验证：

- `spread-dashboard` 可正常启动，原有内部页面仍可访问。
- 六个首页核心入口完整存在，内部路由保持不变。
- USDA 与 Oil World 仍由环境变量解析；变量缺失时首页不崩溃。
- 人工维护数据不显示为自动实时更新；周度数据不因非当天日期被误判异常；`partial_failure` 不显示为完整正常。
- 普通笔记本与窄屏下的标题、状态、按钮和主要文本不溢出，不依赖横向滚动阅读。
- 既有核心测试、Python 语法检查和 `git diff --check` 通过。

## 停止点

完成项目说明和页面契约后停止。本轮不修改 `05_apps/`、测试、数据、部署、Git 历史或生产环境；进入 UI 开发前需获得下一阶段确认。
