# 数据与输出规范

> 文档状态：当前权威文档。本文定义当前通用数据和输出边界；具体模块 Schema、业务公式和质量门槛由项目契约或源码测试定义。

## 1. 基本原则

- 数据更新与代码部署是两个独立流程。
- 部署不得顺带覆盖运行数据；数据更新不得隐式替换代码。
- 人工原始文件不得被程序主动改写。
- 稳定数据切换前必须完成候选校验、备份或可恢复性检查。
- 生产数据、日志和输出不因 Git 中不存在而可以删除。
- 敏感数据、凭据、授权原始资料和运行日志不得进入普通 Git 提交。

## 2. `01_data/` 职责

`01_data/` 保存正式运行数据，不纳入普通 Git 发布，部署时不得覆盖、清空或删除。

推荐职责：

| 路径 | 职责 |
|---|---|
| `manual/` | 人工维护或人工放入的源文件 |
| `raw/` | 外部原始数据及来源 Manifest |
| `incoming/` | 待校验的一次性上传入口 |
| `interim/` | 可重新生成的中间数据 |
| `candidates/` | 数据更新候选文件 |
| `processed/` | 清洗、标准化后的稳定数据 |
| `database/` | 页面和业务流程读取的正式数据库 |
| `backups/` | 原子切换或自动更新产生的恢复副本 |
| `cache/` | 可重新生成的缓存 |
| `update_status/` 或状态 JSON | 更新状态、业务日期和失败摘要 |

具体目录存在性以源码和项目契约为准，不得为了满足文档描述而创建无业务用途的空目录。

## 3. 当前主要数据边界

### 3.1 价差数据

- 价格底座：`01_data/historical_price_long.xlsx`
- 价差 Excel：`01_data/historical_spread_database.xlsx`
- 价差 Parquet：`01_data/historical_spread_database.parquet`
- 状态：`01_data/update_status.json`

主工作台在 Parquet 存在时优先读取 Parquet，否则回退到 Excel。不得继续使用“看板只读取 Excel”的旧规则。

### 3.2 国内基差和一口价

- 正式原始数据：`01_data/manual/榨利表/油脂油料价格.sql` 的 `basis_price` 表
- 历史人工母版：`01_data/manual/basis/国内现货基差.xlsx`（只读备份和人工核对，不再生成正式数据库）
- 标准化目录：`01_data/processed/basis_spread/`
- 标准基差：`01_data/processed/basis_spread/国内现货基差_标准表.csv`
- 标准价差：`01_data/processed/basis_spread/国内现货价差_标准表.csv`
- 标准一口价：`01_data/processed/basis_spread/国内现货一口价_标准表.csv`
- 期货收盘价：`01_data/processed/basis_spread/内盘期货收盘价.csv`
- 正式数据库：`01_data/database/basis/basis_quotes.parquet`
- 运行回退：`01_data/database/basis/basis_quotes_sample.parquet`
- 测试固定样例：`08_tests/fixtures/basis_quotes_sample.parquet`

生产回退文件和测试 fixture 职责分离。程序流式读取 SQL，不得主动改写 SQL 或历史 Excel。

标准价差 CSV 使用便于人工识别的中文文件名，但程序接口字段保持英文。例如：

| 字段 | 示例 | 含义 |
|---|---|---|
| `date` | `2026-07-18` | 业务日期 |
| `spread_name` | `M09-M01` | 价差组合名 |
| `spread_value` | `125.5` | 价差值 |
| `source_sheet` | `豆粕` | 原始工作表来源 |

### 3.3 美豆种植生长

- Stable Progress：`01_data/processed/soybean_crop_progress/soybeans_crop_progress_weekly.parquet`
- Stable Condition：`01_data/processed/soybean_crop_progress/soybeans_crop_condition_weekly.parquet`
- Raw/Manifest：`01_data/raw/soybean_crop_progress/`
- Candidates：`01_data/candidates/soybean_crop_progress/<run_id>/`
- Backups：`01_data/backups/soybean_crop_progress/<UTC时间>/`
- 状态：`01_data/update_status/soybean_crop_progress.json`

两个稳定 Parquet 必须作为同一批次验证和切换，不能形成 Progress/Condition 跨批次组合。

### 3.4 USDA 与 Oil World

- USDA 原始数据、正式生成数据和快照边界以 USDA 项目契约为准。
- Oil World 授权原始资料必须保存在 Git 仓库外，由环境变量或忽略配置定位。
- Oil World 被 `releases.json` 和 `latest.json` 引用的 release/comparison 属于受控发布数据，不得散拷或随意删除。

## 4. `06_outputs/` 职责

`06_outputs/` 保存程序生成结果，不纳入普通 Git 发布。常用子目录：

| 路径 | 职责 |
|---|---|
| `charts/` | 图片和图表 |
| `excel/` | Excel 报告 |
| `markdown/` | Markdown 日报和研究摘要 |
| `push_logs/` | 邮件、飞书等推送结果 |
| `audits/` | 数据更新和运行审计证据 |

输出目录不得保存密码、Token、API Key、SSH 私钥或完整敏感环境。推送日志只能记录非敏感结果和错误摘要。

动态看板与静态导出职责分离：

- 日常页面可以直接读取稳定数据库；
- PNG、Excel 和 Markdown 是按需导出物；
- 页面不得无必要依赖某个静态导出目录才能启动；
- 旧版 `06_outputs/reports/current` 不能作为新的通用输出标准，除非仍有具体脚本明确引用并由项目契约登记。

## 5. 字段、文件名和接口稳定性

- 标准 CSV、Parquet 和 JSON 的字段名保持英文。
- 中文含义、单位、来源、空值和口径写入数据字典或项目契约。
- 面向用户直接打开的报告和图表可以使用中文文件名。
- 程序内部数据库、模块、配置键和稳定接口优先使用英文名。
- 已被脚本、应用、定时任务或测试引用的文件名不得仅为美观而改名。
- 日期、时区、自然年、市场年和作物年度必须显式记录，不能依靠字段名猜测。

每个正式数据契约至少应定义：

1. 权威来源和认证变量名；
2. Schema、类型、单位和允许空值；
3. 唯一键和重复处理；
4. 更新频率、时区和业务日期；
5. 修订、幂等、异常停止和回滚；
6. raw、candidate、stable 和 backup 路径；
7. 宿主机路径、容器路径、写入主体和只读边界。

## 6. 数据更新安全

数据更新前必须：

- 确认输入绝对路径、大小、可读性和必要的 SHA-256；
- 确认没有另一更新进程持有锁或正在执行；
- 检查历史行、唯一键、日期、品种和关键字段；
- 明确正式文件、候选文件、备份和状态文件；
- 明确失败时哪些对象保持不变。

更新成功不能只依据命令退出码，还应验证：

- 记录数和最新业务日期；
- 关键主键和重复；
- 稳定文件可读性和 SHA-256；
- 状态文件；
- 页面或下游读取；
- 临时上传入口是否按契约清理。

## 7. Git 和部署边界

普通 Git 提交不得包含：

- `01_data/` 运行数据；
- `06_outputs/` 生成结果；
- `10_logs/`；
- `.env` 或服务器环境文件；
- 授权原始资料；
- 密钥、Token、Cookie、密码或私钥；
- 未明确批准的缓存和临时产物。

例外只能是经过项目契约确认的静态发布资产，例如 USDA 正式 `public/data/`。例外文件仍必须通过显式路径暂存和差异审查。

部署必须保护：

```text
01_data/
06_outputs/
10_logs/
.env 及正式环境文件
```

候选容器如需正式数据，只允许只读挂载；缓存、日志和临时文件必须写入候选隔离目录。

## 8. 备份、保留和清理

- 人工原始文件、唯一授权资料、当前生产数据和唯一有效备份不得删除。
- 当前正式镜像、已验证回滚镜像和密封发布证据按发布规范保留。
- 日志固定保留期限尚未确认前，不得批量删除。
- 可重新生成的缓存和中间文件只能在独立清理任务中处理。
- 删除前必须检查容器挂载、页面引用、定时任务、恢复来源和审计链。
- 禁止使用 Docker prune 或未经清单确认的递归删除代替对象级盘点。
