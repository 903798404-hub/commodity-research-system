# 异步数据更新合同

> 状态：Domestic Basis 试点设计合同已主线生效；后续六域推广与有证据 Missing 非阻断已另行闭包并验收。本文保留本试点的业务语义，不重新定义其他域政策。逐 series freshness 阈值仍未批准；本文不授权 Git 提交、生产启用或真实运行。当前执行身份必须重新在线核验，不从历史阶段记录推导。

## 1. 身份与增量分离

`Next Candidate = Existing Current upsert Valid Increment`。Increment 的查询窗口是读取范围，不是删除范围，也不是完整 dataset 的身份定义。

Identity Coverage 对最终 Next Candidate 的稳定 identity 集与 required identity 集做严格差集比较。缺失或意外 identity 均阻塞；变更 mapping 不能静默缩小已有 Current 的 identity lifecycle。生命周期增删须另行明确批准，不由本合同自动推断。

上游独立 inventory → 实际提取 → Standard → 合法 Canonical groups → 完整 Next State 的计数、身份与 lineage 必须一致。保留 Current 不能掩盖真正丢失的合法 source 数据。

## 2. 独立状态维度

不再使用 UPDATED / NO_CHANGE / STALE / ERROR 四选一枚举。

| 维度 | 状态 | 回答的问题 |
|---|---|---|
| coverage_status | PRESENT / MISSING / ERROR | Required stable identity 是否存在、是否能信任其完整性 |
| update_status | UPDATED / NO_CHANGE / ERROR | 本轮合法新日期是否进入 Next State，或是否发生更新错误 |
| freshness_status | FRESH / STALE / UNASSESSED | 当前最新合法业务日期是否满足已批准阈值；无已批准阈值不能评为 FRESH |

`NO_CHANGE + STALE`、`UPDATED + STALE` 都是合法组合。STALE 不覆盖 update_status；UNASSESSED 不使 coverage 或 update 自动变成 ERROR。真实丢失 identity、无法验证的来源、mapping、normalization、schema 或 candidate 损坏仍 fail closed，错误数据的 freshness 为 UNASSESSED。

同日期修订或回填 older key 不伪称为新日期：update_status 为 NO_CHANGE，另记 `revision_row_count`；freshness 独立判断。Dataset 有真实业务内容变化时仍为 UPDATED。这一 NO_CHANGE 表示“最新业务日期无推进”，不表示“绝无历史修订”。

Dataset 归约：真实 ERROR / identity loss / dataset 指定 blocking STALE → FAILED；非阻塞 STALE → WARNING；有新增或修订 → UPDATED；否则 NO_CHANGE。没有阈值时的 UNASSESSED 不阻断，也不伪装成 FRESH。WARNING 保留独立 updates 统计。

本轮不修改统一 provider 枚举和事务实现；Domestic Basis 的 WARNING 保留在自身 summary 中，统一层仍按实际是否 promotion 使用既有 UPDATED/NO_CHANGE。其他 producer 不迁移。

## 3. Freshness policy

纯函数位于 `03_src/agri_research_agent/shared/async_update.py`：`FreshnessPolicy`、`SeriesUpdate`、`evaluate_update`，无 I/O、数据填充或生产开关副作用。

最小 dataset-level 参数：

```yaml
policy_version: <version>
threshold_approved: false
age_basis: calendar_days
freshness_threshold: null
stale_is_blocking: false  # Domestic Basis 已批准；其他 dataset 独立选择
```

- `freshness_threshold` 为 null 或非负整数；只有 `threshold_approved=true` 且阈值非空时评估。超过（严格大于）才 STALE，等于仍在阈值内。阈值与 `stale_is_blocking` 是独立参数，禁止设置全系统统一 7 天默认值。
- 当前仅实现自然日 age。若业务要求交易日、节假日或分段频率，应先批准和实现 calendar，不得伪装为已支持。
- age = 明确 as-of date − Next State latest valid business date。不以 source 全局最大日期作时钟，不要求 series 日期相等。
- Domestic Basis as-of 为提取时刻转换 Asia/Shanghai 后的日期，仅用于 age，不写入 trade date。
- 无已批准阈值：`freshness_status=UNASSESSED`、逐 series `threshold=null`，仍记录 `latest_date`、可计算的 `age_days`；未实现交易日 calendar 时 `age_business_days=null`。不改变 update_status，不增加 freshness 阻断原因，不限制已有身份/来源/数据质量 gate。
- Domestic Basis 已批准 NO_CHANGE allowed、STALE non-blocking WARNING；threshold 仍为空。现有摘要级 7 天政策保持原样，不迁入逐 series 生产政策。
- 测试政策只用于 synthetic fixtures。不得把测试边界值作为正式政策。

## 4. 机器报告

`async-data-update/2` 包括：dataset、as-of、policy、freshness_assessment_available、identity coverage expected/actual/missing/unexpected、dataset_status、blocking_reasons、promotion_allowed、summary 与 series 明细。旧 `/1` 单枚举报告不可直接作为新 promotion 证据。

Summary 保留 `TOTAL_REQUIRED`，并分别统计 `coverage.{PRESENT,MISSING,ERROR}`、`updates.{UPDATED,NO_CHANGE,ERROR}`、`freshness.{FRESH,STALE,UNASSESSED}`。每个维度的数量之和均严格等于 required 数，禁止跨维度合计。

每个 required identity：previous/source/next latest date、latest_date、new_row_count（兼容字段）/new_rows、revision_row_count、source_window_row_count、coverage_status、update_status、freshness_status、reason、freshness_reason、age_days、age_business_days、threshold。取得 source 前失败时相关日期为 null，不猜测。

如果在 Candidate 组装前失败，整体 coverage gate 标为 `NOT_EVALUATED`，逐 series coverage/update 为 ERROR、freshness 为 UNASSESSED；不能把“没有得到 Candidate”写成“已证实丢失全部 identity”。连 mapping 都无法读取时 `required_identities_known=false`、明细为空、各维度计数为 0，dataset 仍 FAILED；这不是 zero-error PASS。批次中途终止后的未验证 series 以 ERROR / `CANDIDATE_NOT_EVALUATED_AFTER_BATCH_ERROR` 报告，不伪称 NO_CHANGE。审计写入本身失败时保留原异常并附加安全的报告失败类型。
