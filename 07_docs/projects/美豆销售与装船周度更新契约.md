# 美豆销售与装船周度更新契约

> 文档状态：当前项目专项契约，正式数据模型 `schema_version = 1`。本文锁定美豆出口销售与装船周度能力的应用归属、数据生命周期、稳定文件、指标派生、页面读取、测试和运行边界；API 事实以本文登记的两份受控真实探测审计为依据，不得以猜测或聊天记忆覆盖。

## 1. 适用范围与优先级

本项目属于主工作台 `spread-dashboard`，导航归属“美豆周度跟踪”。页面采用两个一级页签：

1. 种植生长；
2. 出口销售与装船。

现有“种植生长”页签及其 NASS 数据链保持不变。本项目只新增“出口销售与装船”能力。

本文同时受根目录 `AGENTS.md`、`07_docs/00_文档索引与适用范围.md`、01–06 当前权威文档和 `农产品研究工作台页面契约.md` 约束。发生冲突时停止，按权威优先级处理。

固定边界：

- 不新增独立容器、端口或 Web 服务；
- 不修改 USDA 或 Oil World 独立应用；
- 不把 FAS 或 FGIS 数据写入 NASS 的两个稳定 Parquet；
- 不把 API 探测、数据更新和代码部署合并为一个隐式流程；
- 页面只读 stable/current 和各自 status，不直接请求外部 API；
- API、Schema、认证、单位、代码和公式的具体事实只有实测并形成审计证据后才可进入正式数据模型。

## 2. 两条独立生产数据管道

本项目包含两条互相隔离的生产数据管道：

| 管道 | 研究职责 | 不承担的职责 |
|---|---|---|
| FGIS Export Inspections | 出口检验、装船节奏及目的地结构 | 不提供或替代出口销售承诺数据 |
| FAS Export Sales Reporting | 净销售、累计出口、未执行销售、总承诺及下一市场年度销售研究 | 不提供或替代 FGIS 出口检验事实 |

两条管道必须分别拥有：

- 独立数据获取入口；
- 独立 raw snapshot；
- 独立 candidate；
- 独立 stable/current；
- 独立 revision history；
- 独立 backup；
- 独立 status；
- 独立 audit；
- 独立 log；
- 独立非阻塞锁；
- 独立失败状态；
- 独立服务器包装脚本；
- 独立 Cron。

FGIS 失败不得阻断、回滚或降级 FAS 已成功更新的数据；FAS 失败也不得影响 FGIS。页面允许两侧显示不同的最新成功日期，并根据各自 status 呈现正常、部分可用或暂不可用。不得为了对齐发布日期回退任一侧已经成功发布的 stable/current。

Cron 的已批准排程、运行用户、时区、密钥路径和固定宿主入口见第 21.4 节；实际安装状态仍必须在后续独立生产任务中确认。本契约不表示 Cron 已安装。

## 3. 数据命名空间与生命周期

两条管道采用相同阶段、不同命名空间：

```text
API
→ immutable raw snapshot
→ normalize
→ candidate
→ validate
→ stable/current + revision history
→ status/audit
```

计划命名空间如下；本轮不创建任何目录或数据文件：

| 对象 | FGIS | FAS |
|---|---|---|
| Raw | `01_data/raw/soybean_export_inspections/<run_id>/` | `01_data/raw/soybean_export_sales/<run_id>/` |
| Candidate | `01_data/candidates/soybean_export_inspections/<run_id>/` | `01_data/candidates/soybean_export_sales/<run_id>/` |
| Stable/current | `01_data/processed/soybean_export_inspections/` | `01_data/processed/soybean_export_sales/` |
| Backup | `01_data/backups/soybean_export_inspections/<UTC时间>/` | `01_data/backups/soybean_export_sales/<UTC时间>/` |
| Status | `01_data/update_status/soybean_export_inspections.json` | `01_data/update_status/soybean_export_sales.json` |
| Audit | `06_outputs/audits/soybean_export_inspections/` | `06_outputs/audits/soybean_export_sales/` |
| Log | `10_logs/soybean_export_inspections/` | `10_logs/soybean_export_sales/` |

正式稳定文件名、Schema、唯一键和 API 字段映射见第 17 至 27 节。两侧稳定文件、Manifest、revision、status 和回滚对象必须保持独立。

### 3.1 Raw snapshot

- 每次成功取得的原始响应或足以无损重建原始响应的快照必须不可变保存；
- raw 必须记录来源、脱敏请求身份、抓取时间、响应 SHA-256、HTTP 状态、Schema 身份和运行 Git SHA；
- 不得只保存最新聚合值，不得原地覆盖旧 raw；
- 认证值、Cookie、Token 和完整敏感请求头不得进入 raw、Manifest、audit 或 log。

### 3.2 Candidate 与校验

- normalize 只从本次已密封 raw 产生 candidate；
- candidate 必须位于独立 `run_id`，不能与 stable/current 共用路径；
- candidate 在 Schema、类型、业务日期、market year、目的地、单位、重复、周序列、修订和跨文件身份全部通过后才可切换；
- API 空响应、HTTP 失败、Schema 漂移或关键身份无法解释时，candidate 失败并保留有限脱敏证据，stable/current 保持不变。

### 3.3 Stable/current、backup 与 status

- 页面只读取每条管道当前最新有效的 stable/current；
- stable/current 切换前必须创建同管道、同批次恢复来源；
- 切换采用临时文件完整写入、格式与 SHA-256 复核、原子替换和切换后复核；
- 失败时只回滚本管道，不触碰另一管道或 NASS 数据；
- status 必须区分最近尝试和最近成功，记录最新有效业务日期、运行身份、失败摘要和 stable 身份；
- 命令退出码不能单独证明更新成功。

## 4. Revision 与历史版本

USDA 周度数据可能对已经发布的同一 `week ending date` 修订。本项目必须同时保留发布历史和当前有效视图。

长期身份至少能够区分：

- 数据源；
- 真实 market year；
- week ending date；
- 原始 release/update 身份；
- fetch 时间与 `run_id`；
- commodity 身份；
- destination/country 身份；
- 指标与单位；
- 原始值和当前有效值。

同一业务周在不同 release/fetch 时点出现不同值时，不得覆盖历史版本。revision history 和 audit 必须能够恢复：

- 第一次观察到的值；
- 当前最新有效值；
- 每次修订的观察时间和来源快照；
- 修订绝对幅度及适用单位；
- 由哪次 stable/current 切换激活。

stable/current 只呈现最新有效值；raw 与 revision history 保留完整可追溯版本。若来源 API 只覆盖历史而不提供历史发布版本，必须如实记录“只能从本系统开始逐次积累修订历史”，不得补造此前版本。

## 5. Market year 与周序列

- 底层永久身份必须保存真实 market year，不得使用 `old_crop`、`new_crop` 作为持久身份；
- 页面根据报告日期和经实测确认的 USDA 市场年度规则动态派生 current marketing year 与 next marketing year；
- 页面可显示“本年度”“下一年度”，但不得把某个固定年度永久写成旧作或新作；
- 跨 9 月切换不得要求每年修改业务代码；
- FGIS market year 按 `cert_date` 归属 9 月 1 日至次年 8 月 31 日；FAS 请求参数是结束年份，current 与 next 目标年度按第 19 节处理；
- 横轴使用 market-year week，tooltip 同时显示真实 week ending date；
- 缺周不得自动插值、补零、前向填充或后向填充，除非后续经过业务契约明确批准。

## 6. Destination、China 与 Non-China

- 底层优先保存来源提供的真实 destination/country 明细及其原始代码和名称；
- FGIS China 固定为原始 `destination='CHINA'`；FAS China 固定为 `countryCode=5700`；香港和台湾均保持独立；
- Non-China 是派生口径，不是原始国家值；
- Non-China 可以在实测证明口径一致后由 `World - China` 计算，或从完整目的地明细聚合；
- 若 World 与目的地明细不一致、覆盖范围不同或存在未分配目的地，必须停止使用简单差额并记录差异；
- 第一版页面重点展示 China 与 Non-China，但数据模型必须保留扩展到其他主要目的地的能力。

## 10. 自动文字原则

自动文字第一版必须使用确定性数据模板。大模型不得直接读取原始 API 并自由生成具体数值。

所有数值、同比、环比、占比、累计值和修订值必须先由 Python 确定性计算、校验并形成结构化事实，再进入文字模板。

文字分为三个独立区块：

1. 出口检验；
2. 本年度销售；
3. 下一年度销售。

未来模板应能表达：

- 最新周、本周值、前一周值及前一周是否修订；
- 去年同期、累计值、累计同比；
- China、China 占比和 Non-China；
- 本年度净销售、累计销售、累计出口、Outstanding Sales 和销售完成率；
- 下一年度销售和 China 下一年度销售。

具体措辞、显著性阈值和异常阈值由后续独立设计确认。本契约不预设阈值。

### 12.2 1983 年至今连续性核验

不得仅凭端点说明或最早一条记录断言“1983 年至今连续”。真实探测必须：

1. 获取端点实际可查询的最早和最新边界；
2. 按真实 market year 和 week ending date 建立年度周序列；
3. 分年度统计记录数、首周、末周、52/53 周、缺口和重复；
4. 区分真正缺周、无业务发布、零值、接口过滤和分页截断；
5. 抽查早期、中期、最近年份的原始响应与聚合一致性；
6. 检查 World 与 destination 合计的覆盖差异；
7. 对所有异常年份形成明细，不把“有记录”误报为“连续完整”；
8. 只有完整性报告通过后，才确定可支持的正式历史起点。

## 14. API 探测审计输出

FGIS 和 FAS 必须生成彼此独立的探测报告，不得合并为一个成功状态。计划输出位置如下，本轮不创建：

```text
06_outputs/audits/soybean_export_inspections/api_probes/<run_id>/
06_outputs/audits/soybean_export_sales/api_probes/<run_id>/
```

每侧至少生成结构化 JSON 和便于人工复核的 Markdown 摘要。报告必须包含：

- 探测时间、运行 Git SHA 和工具版本；
- HTTP 请求身份：方法、endpoint、脱敏参数、请求头名称、请求体 SHA-256；
- 不得输出完整 API Key、Token、Cookie 或认证头值；
- HTTP status、响应媒体类型、响应大小和响应 SHA-256；
- response schema、字段名、推断类型和有限脱敏样本记录；
- 最早/最新日期、最早/最新 market year 和记录数量；
- destination/country 数量、China 身份和 World 表达；
- 单位、缺失字段、空值和重复数量；
- 周序列完整性及 52/53 周情况；

  Yearly update provenance，不得将 Yearly 标识为 `sruw-w49i`；

`sha256` 只能在文件完整关闭后写入旁路 Manifest。status 继续分别记录最近尝试与最近

## 18. FGIS aggregated stable schema v1

### 18.1 行粒度、唯一键和字段

FGIS stable 的一行是一个来源目的地在一个真实大豆市场年度、一个 week-ending 桶内的
聚合。正式唯一键为：

```text
source + commodity + market_year_end + week_ending_date + destination
```

| 字段 | 类型/可空 | 正式含义 |
|---|---|---|
| `schema_version` | int16，非空 | 固定 `1` |
| `source` | string，非空 | 固定 `usda_fgis_export_inspections` |
| `source_dataset_id` | string，非空 | 行级技术来源身份：历史基线可为 `sruw-w49i`，Yearly 增量必须标识 `yearly_export_grain_csv:CYyyyy.csv`；跨渠道共享键可标识为 historical baseline + Yearly，真实双重 provenance 以 Manifest 为准 |
| `commodity` | string，非空 | 固定原始值 `SOYBEANS`；不存在虚构 commodity code |
| `market_year_start` | int16，非空 | 由每条 raw 的 `cert_date` 判定 |
| `market_year_end` | int16，非空 | `market_year_start + 1` |
| `market_year_label` | string，非空 | 例如 `2025/26` |
| `my_week` | int16，非空 | 本 MY 内 distinct `week_ending_date` 升序桶号，从 1 开始 |
| `week_ending_date` | date，非空 | 原始 `date`；同一天可以属于两个 MY |
| `destination` | string，非空 | 原始 destination 标签，不改写香港、台湾或历史标签 |
| `destination_role` | string，非空 | v1 stable 固定 `source_destination` |
| `weekly_mt` | int64，非空 | 该 MY、周、目的地内官方 `mt` 合计 |
| `cumulative_mt` | int64，非空 | 同 MY、目的地按 `my_week` 累计 `weekly_mt` |
| `source_row_count` | int64，非空 | 参与该聚合的 raw 明细行数 |
| `source_fetch_id` | string，非空 | 本次 fetch/run 身份 |
| `batch_id` | string，非空 | 本次 candidate/stable 批次身份 |
| `raw_snapshot_id` | string，非空 | 不可变 raw 快照身份 |
| `raw_snapshot_sha256` | string，非空 | 对应 raw Manifest 或快照内容身份 |
| `source_dataset_updated_at` | timestamp UTC，可空 | 数据集级更新时间；不是 USDA 周报发布时间 |
| `fetch_time_utc` | timestamp UTC，非空 | 本系统抓取时间；不是官方 revision/release 时间 |

Socrata raw 的 22 个字段保留于已验证历史快照。Yearly 每次 SHA 变化时必须
无损保留官方 `CYyyyy.csv`，并保留映射后的同等 raw 语义；`MKT YR` 只作源
审计字段，不参与 MY 计算。stable 仍只保存研究所需聚合和追溯身份。
`pounds` 仅做交叉校验，正式量值使用 `mt`，展示万吨时除以 10,000。

### 18.2 Market year 与 MY week

每条 raw 必须先用 `cert_date` 分配大豆 MY：9 月 1 日至次年 8 月 31 日。完成分区后，
才允许按 `market_year_end + week_ending_date + destination` 聚合。不得先按
`week_ending_date` 汇总再分 MY。跨 9 月 1 日的同一 `week_ending_date` 可在旧、新两个
MY 各有一组行。

`my_week` 是该 MY 实际 week-ending 桶的序号，不是 API `week` calendar week。模型
接受 53 桶、54 桶和首尾部分周，也允许当前或最早历史是部分 MY；不得截断、合并或补成
固定 52/53 点。缺失桶保持缺失，不插值、不前后填充。

### 18.3 Destination 角色

- 来源 China 是 `destination='CHINA'`；`HONG KONG`、`TAIWAN` 始终独立。
- `World` 是同键范围内全部 `source_destination` 的合计，不是来源行。
- `Non-China` 是全部目的地排除 `CHINA` 的合计，并必须等于 `World - China`。
- 页面派生视图使用 `research_world`、`research_china`、`research_non_china` 角色；这些
  角色不写回 FGIS stable 的 `destination`。
- 只有完整分页、无汇总伪行且闭合检查通过时，某周没有 `CHINA` 行才可在派生层解释为
  China `0 MT`；否则保持缺失并停止发布。

并保留转换规则版本。不得添加 `Z`，不得让派生 UTC 替换原始 release 身份。

### 19.2 report week 与标准化目标年度视图

`report_week` 由同一 `report_market_year_end` 的商品级 distinct `week_ending_date` 升序
编号，从 1 开始；不能按单个国家出现的首周编号。current 和 next 字段共享同一个
`report_week`。国家缺行保持来源缺失，只有整份 allCountries 响应完整性通过后，派生聚合
才可按 API 语义处理未出现国家。

页面标准化视图至少包含：

```text
report_market_year_end
target_market_year_end
target_market_year_role = current | next
report_week
week_ending_date
country_code
weekly_net_sales_mt
cumulative_sales_or_presales_mt
```

- current 行：`target_market_year_end = report_market_year_end`；累计销售取
  `current_my_total_commitment_mt`。
- next 行：`target_market_year_end = report_market_year_end + 1`；累计预售取
  `next_my_outstanding_sales_mt`。
- next 行的日期仍是 report MY 的观察周，不定义、不保存 `target_my_week`。例如 report
  MY 2025/26 在 2026-07-30 观察到的 2026/27 预售，其 `report_week` 属于 2025/26。
- 下一年度季节性同比按相同 `report_week` 比较相邻 report MY 的 next 序列，即比较不同
  年份在相同观察进度下对各自下一目标 MY 的预售。

### 19.3 China、Non-China 和指标闭合

- China 固定为 `country_code=5700`；5820 Hong Kong、5830 Taiwan 不合并。
- World 是同一来源周全部国家行合计，不是 API country 行。
- Non-China 是全部 `country_code != 5700` 的合计，明确包含 9990 Unknown。
- 页面派生角色为 `research_world`、`research_china`、`research_non_china`，不回写 stable。
- 以下 7 个指标每周都必须满足 `World = China + Non-China`：周出口、累计出口、当前
  outstanding、当前周度净销售、当前总承诺、next outstanding、next 周度净销售。

## 20. 正式指标与 USDA 销售完成率分母

### 20.1 FAS current 与 next

| 研究指标 | 正式字段/公式 | 约束 |
|---|---|---|
| 本年度周度净销售 | `current_my_net_sales_mt` | 允许负值 |
| 本周出口 | `weekly_exports_mt` | API 原生 |
| 本年度累计出口 | `accumulated_exports_mt` | API 原生，不从周出口另算正式值 |
| Outstanding Sales | `outstanding_sales_mt` | API 原生存量 |
| 本年度累计销售 | `current_my_total_commitment_mt` | 不得从本 MY 首周累计 net sales |
| 下一年度周度净销售 | `next_my_net_sales_mt` | 允许负值 |
| 下一年度累计销售/累计预售 | `next_my_outstanding_sales_mt` | tooltip 必须说明“下一 MY 尚未执行的预售承诺存量” |

每个 current 国家行及 World 聚合必须严格满足：

```text
current_my_total_commitment_mt
= accumulated_exports_mt + outstanding_sales_mt
```

不闭合即拒绝 candidate。next 数据没有 next-MY exports 字段，不得把
`next_my_outstanding_sales_mt` 命名为 accumulated exports。

### 20.2 销售完成率的只读 USDA PS&D 契约

分母已经能够从现有正式结构唯一确定，不再 blocked：

1. 数据制度是 USDA FAS **Production, Supply and Distribution (PS&D)**，不是本模块
   另行读取 WASDE，也不是 FAS ESR 字段。
2. 先读取 `11_独立应用/USDA平衡表/public/data/report_version.json` 的
   `currentReportMonth`，再读取同月
   `public/data/snapshots/usda_psd/<currentReportMonth>/matrix/2222000_US.json`；同时与
   `public/data/matrix/2222000_US.json` 的当前视图交叉核验，身份或内容不一致即缺失。
3. 必须精确匹配 `commodityCode='2222000'`、`commodity='Oilseed, Soybean'`、
   `countryCode='US'`、`country='United States'` 和 row `name='出口量'`。该中文行由正式
   构建规则映射自 USDA 原始 `Attribute_Description='Exports'`。
4. 该 matrix 的 `years` 使用市场年度起始年；FAS `target_market_year_end = E` 匹配
   matrix year `E - 1`。不得简单取 matrix 最大年份作为 current MY 分母。
5. 正式构建把原始 `1000 MT` 或 `(1000 MT)` 除以 10 后写成万吨；分母 MT 为 matrix
   值乘 10,000。非该单位、值为空、非正数、年度不唯一或最新报告月身份不完整时 KPI
   缺失，不能回退旧月或其他指标。
6. 销售完成率为 `World current_my_total_commitment_mt / psd_us_soybean_exports_mt * 100`。
   结果可以超过 100%，不得截顶。

本轮只读事实为：最新正式报告月 `2026-07`；2025/26 对应 matrix year `2025`，出口预测
`4,136.8 万吨`（`41,368,000 MT`）；2026/27 对应 year `2026`，为 `4,517.8 万吨`。
页面 current MY 2025/26 的分母必须使用前者。后续实现不得复制这些数值或 USDA 文件到
本模块；运行时始终按上述契约读取最新正式快照。

## 21. Raw snapshot、revision 与更新范围

### 21.1 Revision 记录

两侧当前 API 都只能返回最新修订状态，无法重建首次正式采集前的 initial value。bootstrap
历史统一标记 `initial_value_known=false`；不得把 bootstrap 值声称为历史初值。

首次正式采集后，对 stable 业务键逐字段比较。每条 revision 至少保存：

```text
schema_version, source, business_key_json, field_name, metric_unit,
old_value, new_value, delta, first_seen_fetch_id, revised_fetch_id,
first_raw_snapshot_id, revised_raw_snapshot_id, detected_at_utc
```

`detected_at_utc` 是本系统发现时间，不是 USDA 官方 revision 时间。相同 raw/stable 输入
重复运行不得产生重复 revision；revision 文件只能 append-only 发布，不能随 stable 覆盖。

### 21.2 FGIS 抓取策略

- 历史基线：继续使用已验证 FGIS 历史 stable；首次 Yearly 生产观察后视为
  frozen historical baseline，不为上线前历史补造 initial value 或 revision。
- 常规 weekly：只请求运行时当前自然年
  `https://fgisonline.ams.usda.gov/exportgrainreport/CY{YYYY}.csv`；`YYYY` 必须动态
  取运行时当前年，不得写死。
- 生产服务器正式获取链路固定为
  `09_deploy/soybean_exports/run_fgis_yearly_update.sh`：宿主使用有限次数的 curl Range
  续传写入隔离 `.downloading`，校验下载前后 Content-Length/Last-Modified、严格 UTF-8、
  CSV 关键字段和完整文件 SHA-256 后原子更名；随后把 source 目录只读挂载给无网络容器，
  通过 FGIS CLI `--source-file` 和显式 metadata sidecar 进入现有 Yearly parser、candidate、
  validate 与 stable 流程。该入口不依赖 Python requests 完整下载成功；原有 HTTP adapter
  继续用于 Windows 开发和普通网络环境，但不是生产唯一下载器。
- 文件 SHA-256 与上一次成功处理的同年文件一致时记录 `no_change`，不写新
  raw、candidate、stable 或伪 revision；ETag 和 Last-Modified 只是提示，不代替 SHA。
- SHA 变化时保存不可变官方 CSV 和标准化 raw，将本次当前自然年事实与本系统
  上一次观察到的同年事实做差额，只对实际观察到的新记录、新周和当前
  自然年历史周修订生成 revision。
- unified stable 为 `Frozen historical baseline + Current calendar-year Yearly facts`；必须按
  现有稳定键做差额合并，重算统一 MY week/cumulative，不得删除或重建其他自然年。
- 12 月→1 月后 active file 自动切换到新 CY，旧 CY 转为冻结历史；MY 仍先按
  `Cert Date` 切分再按 `Thursday` 聚合，不因自然年文件切换重置 MY week。
- 本系统只承诺追踪正式上线后在 active 当前自然年文件中观察到的新周和修订。
  USDA 对旧自然年文件的后续修改不主动追踪；不实施当前+上一年周抓取、
  月度全历史 reconciliation 或旧年度 revision watch。

### 21.3 FAS 抓取策略

- 首次 bootstrap：逐个请求参数抓取 1985（部分 MY）至当前非空 report MY；1985 必须标记
  partial，1986 是首个完整参数。metadata 与每个响应分别密封。
- 常规 weekly：先读取 commodity 801 的 `datareleasedates`；release 身份未变时记录
  `no_change`，不得重发 stable。发生变化时重取最近 7 个非空 report MY，足够首版页面
  历史和该范围 revision 检测；current 与 next 始终从每个 report MY 的同一响应取得。
- 历史 reconciliation：每月重取 1985 至当前全部非空 report MY，检测最近 7 个 MY 之外
  的修订。API 没有历史 release version，因此只记录本系统两次快照差异。
- 每次都核验 12 字段、商品/单位 metadata、完整周轴、响应行数、China 指定 endpoint
  子集和 7 指标闭合；`200 []` 只有在请求身份预期可为空时才是合法无数据。

Raw 使用各自 `<run_id>` 下的压缩无损 JSON/JSONL 与 Manifest；压缩不改变不可变、可重建
和逐响应 SHA-256 要求。raw 不进入 stable，密钥和认证头值绝不落盘。

## 22. 页面只读派生层与历史比较

页面不得直接读取 raw、candidate、revision 或外部 API，只读取两侧已验证 stable、Manifest
和 status，并在内存建立以下可重建视图：

- FGIS：weekly/cumulative World、China、Non-China，weekly China share，以及 current MY
  在相同 `my_week` 的 cumulative YoY。
- FAS current：World/China/Non-China 周度净销售与累计销售，World 累计出口和
  Outstanding Sales。
- FAS next：World/China/Non-China 周度净销售与累计预售。

正式比较规则：

- FGIS 只按相同 `my_week` 比较，不按 calendar date；54 桶继续显示，较短或部分 MY 没有
  对应桶时返回缺失。
- FAS current 只按相同 `report_week` 比较相邻 `report_market_year_end`。
- FAS next 也按相同 `report_week` 比较相邻 report MY 的 next 观察值；比较对象的
  `target_market_year_end` 同步相差 1。不得按 target MY 的日历周对齐。
- 同比百分比统一为 `(current - comparison) / abs(comparison) * 100`；比较值为 0、缺失或
  键不唯一时返回 `null`。MT 绝对差仍可独立显示。
- 来源缺行、无可比周和 partial 尾部保持 `null`；不能补零、插值、前向填充或回退到较早
  stable。只有第 18.3 和 19.2 节明确允许、且完整性通过的聚合零值例外。

## 24. 顶部四个 KPI

| KPI | 数据源和公式 | MY/比较基准 | 单位与缺失行为 |
|---|---|---|---|
| 累计出口检验同比 | FGIS current MY 最新 `my_week` 的 World cumulative；与 previous MY 相同 `my_week` 比较，按第 22 节同比公式 | current `market_year_end` 对 previous `-1` | 百分比；任一桶缺失、previous 为 0 或 stable/status 无效则显示“暂无可比数据” |
| 本年度销售完成率 | FAS World `current_my_total_commitment_mt / USDA PS&D US soybean Exports forecast MT * 100` | 分子和分母必须同一 `target_market_year_end`；分母按第 20.2 节最新正式报告月选择 | 百分比，可超过 100%；分母缺失/非正/身份不一致时显示“分母暂不可用”，不得用旧值 |
| 下一年度累计销售 | FAS World 最新 `report_week` 的 `next_my_outstanding_sales_mt` | 显示 report MY 与 `target_market_year_end=report+1`；可附 previous report MY 同周绝对差/同比 | 万吨；最新周或完整聚合缺失时显示暂无数据 |
| 中国下一年度累计采购 | FAS `country_code=5700` 最新 `report_week` 的 `next_my_outstanding_sales_mt` | 与上一 report MY 相同 `report_week` 的 China next 预售比较 | 万吨；China 身份、周或 stable 无效时显示暂无数据，不合并港澳台 |

错误，页面必须分别标示；不得为对齐而回退任一稳定数据。

## 26. Schema 演进与迁移

- 首版固定 `schema_version = 1`，两个来源分别版本化；一侧升级不强迫另一侧同步升级。
- API 新增非关键字段时，raw 无损保留并发出审计提示；在契约、fixture 和消费者均未升级
  前，不得静默加入 stable。确认是可选、非破坏字段后可在同一主版本追加 nullable 列，
  但必须更新 schema hash、文档和测试。
- 任一必需字段消失、重命名、类型/单位/含义变化，或唯一键、MY、周序、指标公式变化，
  都是破坏性漂移：拒绝 candidate，stable 保持不变。
- 删除/重命名列、改变类型或业务键、改变历史值解释时必须提高 schema version，编写显式
  migration；从 immutable raw 或旧 stable 在 candidate 路径重建，完成逐行数、键、总量、
  revision 和页面消费者双读对比后才允许原子切换。
- migration 不得就地改旧 stable；旧文件、Manifest 和回滚对象至少保留到新版本稳定、
  数据结果密封且另获清理授权。
- 页面只接受明确列入兼容矩阵的 schema version。未知主版本直接显示该来源暂不可用，
  不得降级猜字段。
