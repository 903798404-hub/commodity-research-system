# 农产品持仓与资金情绪契约

> 当前项目专项契约。目标是直观观察多空倾向及其增强、减弱，不把持仓变化解释为现金流入流出。页面沿用主工作台“外资与重点席位”入口，旧矩阵页面被四板块选择器替换。

国内大商所官方入口曾返回HTTP 412及HTML脚本，未取得真实持仓ZIP。这不证明用户IP被封或必须购买权限。新浪响应按合约、日期、表头、连续排名及合计校验，与交易所交叉核对的覆盖有限；来源明确标注为新浪。其账户类型保持未区分。

用户已确认国内品种汇总优先：02_configs/oilseed_positions.json 的 default_scopes 为 M、Y、P，速览和国内统计范围首先显示品种汇总。已保存单合约参考仍可选择并保留实际报告日期，不能冒充全品种，也不自动拼接为主力连续持仓；没有有效汇总时显示缺口，不回退单合约替代。

已验证汇总继续保留，国内统计范围优先选择M、Y、P。aggregation=disclosed_contracts_v1口径：各合约已披露多空排名按会员及账户分别合并，合并后重新排名并观察前20/前5；不是直接把各合约前20合计冒充品种前20。五家固定席位分别累加各合约已披露仓位，记录每侧上榜合约数。称为“全合约已披露持仓汇总”，不称完整席位持仓；某合约未上榜部分未知，某侧在所有合约均未出现时保持缺失，不补零。

浏览器采集保存当日来源列出的完整合约清单和每个合约的可见多空排名。导入逐一核验合约选择、标题、日期、连续排名和表内合计；少一个合约、少一侧或数据错误则整份文件不发布。访问完完整清单后，页面最近报告早于目标日期的合约明确排除并保存日期/原因，不混入当日汇总。大商所公开排名还受合约披露门槛限制，不声称覆盖所有上市月份或所有账户。

历史东方财富浏览器多空排名及新浪单合约参考保留原来源、账户和完整合约清单。M/Y/P 服务器自动任务经显式 positions_stock_api 配置调用下述用户指定 Tushare 兼容 HTTP 服务，复用分页、日期、合约、多空完整性校验，按席位重新汇总；页面标注实际来源，不把新报告称作东方财富或 Tushare 官方直连。新旧来源、账户或合约范围不同不直接拼接净变化。

其他接口核查：官方[Tushare fut_holding](https://tushare.pro/wctapi/documents/139.md)支持合约或产品代码、日期范围及DCE，返回会员多空持仓与变化，单次2000条、最低2000积分；官方[RQData futures.get_member_rank](https://www.ricequant.com/doc/rqdata/python/futures-mod)支持合约或品种，long/short分别查询，并支持历史日期范围，[需试用或正式账户](https://www.ricequant.com/doc/rqdata/python/manual)。尚未取得账户授权和实际样本，不能声称M/Y/P汇总覆盖、账户分类或展示授权已验证，不预装SDK或保存凭据。AKShare的futures_dce_position_rank封装同一大商所batchDownload地址，不是独立备用来源；futures_hold_pos_sina仅提供单合约排名。具体实测及公开原始行情响应保存在06_outputs/commodity_positions，未改写持仓快照。

Euronext新版只采纳明确标注FUTR/COMB的报告。2022年起、2026-09-30以前的官方单表历史，可由独立`euronext_legacy_YYYYMMDD`来源重放：严格核对官方URL、ECO/XMAT、EURONEXT PARIS、统计日/发布日期、NEWT或AMND状态、五分类、多空列及明细合计；必须没有Report type字段。归入期货＋期权（Delta等价手），标记`report_basis=mifid_legacy_combined_v1`，绝不生成早年纯期货值。普通解析器仍拒绝未标注口径的文件，越过历史日期边界、混表或有未知Report type都拒绝。

历史口径依据：[ESMA 2024最终报告第4节](https://www.esma.europa.eu/sites/default/files/2024-12/ESMA74-2134169708-7577_Final_Report_on_the_amendments_to_certain_technical_standards_for_commodity_derivatives.pdf)说明新增排除期权的第二份周报；[ESMA最终上线公告](https://www.esma.europa.eu/press-news/esma-news/esma-confirms-go-live-weekly-commodity-derivatives-position-reporting)确认监管v2于2026-09-03启用；原始HTML实测2026-09-09/16/23仍为旧单表，09-30起为明确FUTR/COMB双表，因此HTML边界另定为09-30，不把监管上线日当作页面格式切换日。旧合并报告与新版COMB按同一基金分类、合并范围和Delta单位对比，原始格式来源分别保留。有此历史时菜籽外盘默认合并口径，以展示五年对比；纯期货仍可选择并明确早年未单列。期权合并持仓保留两位小数，分类之和不冒充总持仓。CFTC管理基金与Euronext投资基金分别观察，不跨市场合并手数。

Euronext官方说明每周三下午发布上周五收盘持仓。按Europe/Paris（含夏令时）判断，
未来发布日期和当地当天中午前的文件不请求，沿用`not_published`状态；中午只是最早允许检查的界限，不保证届时已发布。
到达检查窗口后及历史文件的403、网络或解析错误仍按原规则失败，不伪装成尚未发布。
次轮原定时检查继续获取已发布报告；发布日期与实际持仓统计日分别保留，其他来源和数值口径不变。

## 页面与计算

- 默认显示资金情绪速览，净仓、多空方向、变化及实际截至日期；红表示向多，绿表示向空，不能单看颜色推断价格涨跌。
- 净持仓＝多仓－空仓。变化为相邻已保存同市场、同口径、同交易者分类及同合约/账户的差值；显示比较日期，间隔超过10天不计算变化。
- 国内前20/前5多空名单可以不同，变化包含名单更替；不是全市场净持仓。
- 五家固定席位为高盛/乾坤、摩根大通、永安、国泰君安、东证。按用户确认的文华口径计算国内榜内净仓：未披露一侧仅在派生计算中按0处理，原始记录及席位多空字段仍保留缺失，不补造排名记录；两侧均未披露时榜内净仓为0，不代表实际零仓位或多空平衡。五家合计为五家榜内净仓之和，披露覆盖继续单独显示。默认郑商所代客，其余来源未明确账户类型时保留未区分；无有效报告不生成净仓。
- 合约汇总榜内净变化按两份已保存汇总的榜内净仓之差计算，不把席位表“增减”机械相加当作重新排名后前20净变化，变化包含席位进出排名。派生指标标记`ranked_missing_zero_v1`；不改变源数据、归档及存储格式。来源、账户或聚合方法不同不混比；合约清单变化时净变化缺失并标明原因。五家合计不保证未上榜部分完整。东方财富明确标注代客；旧新浪单合约仍保留未区分。外盘分类持仓继续保留缺失，不采用补零规则。
- 用户已移除前20与前5的双线对比、账户类型选择器和大标题下方说明；保持直接标注的五家曲线、变化柱状图、中文日期与简短情绪解释。
- 外盘净仓曲线与变化柱图、国内固定席位曲线与前20名变化柱图分别两张一行，同时可见，高340像素；宽度随列容器伸缩，窄屏自动上下排列。菜籽国内统计范围首次打开默认菜油OI，用户仍可切换RS及RM；不改变各品种统计口径。
- 页面只读，不下载数据、不运行更新、不访问旧foreign_seat_positions.parquet。没有真实数据时展示缺口，不提供示例走势。快照损坏或属于其他板块时停止展示并报错。

## 存储、采集与数据交付

### 持仓季节性

- 所有外盘板块默认展示公历年季节性，可切换连续历史；季节性指标可选净持仓、多仓、空仓，默认净持仓。各市场、报告口径、交易者分类、单位分别对比，不跨市场相加。
- 横轴按月日对齐（闰年2月29日单独保留），图例显示年份，默认最近五个已有年份，全部已保存年份可选。当年按北京时间标记并使用统一红色加粗，悬浮显示真实持仓统计日期及原始单位；Delta等价手保留小数。无历史不造曲线，仅一年时明确提示。净变化柱图继续按真实报告日期显示。
- 季节性不补造观测、不延长至年末，缺值断线，报告间隔超过10天或来源/聚合方法变化断线。不同合约不拼接。选择年份仅影响季节性，指标及变化柱图继续展示当前口径最近报告。
- 外盘季节性及连续历史图标注最新报告的实际持仓日期、指标手数和较上期变化。季节性筛掉最新报告所在年份时取消标注。多仓和空仓仅用两期均披露的同侧数据计算变化，缺少可比值时显示暂无可比数据。
- 白糖国内另设中粮期货代客席位（会员名称严格匹配“中粮期货”或“中粮”），不加入或改变原五家合计。按所选SR品种/合约及截至日期，分别展示多仓、空仓、榜内净仓三张年度季节性图及明细。沿用榜内净仓计算，原始未披露多空仍为空，两侧均未披露时季节性点留空；没有任何披露时显示缺口。中粮期货会员排名不代表中粮集团完整或自营持仓。
- 高盛独立季节性复用当前范围及截至日期的五家排名中高盛/乾坤席位数据，独立展示三张白糖持仓图及明细。高盛和中粮的图内标注截至日期、最新持仓及同口径日度变化，合约范围或统计口径变更时不跨期计算。最新值未披露时在图内提示。
- 此功能仅读取既有完整公开排名，无新增采集、历史回填、存储格式或定时任务变更。

### 服务器直接采集内盘持仓

新增独立入口`04_scripts/positions/collect_server_positions.py`及`positions.server_collection`，可在Linux服务器或本地开发环境直接调用用户提供的第三方Tushare兼容服务`https://t.xiaodefa.top/`。来源标记为`stock_api`，不是Tushare官方直连；token仅从`STOCK_API_TOKEN`进程环境读取，不写入Git、原始响应归档、结果、页面或错误日志。请求使用gzip、明确交易日、DCE交易所及有界分页；原始归档保存闭合的请求身份和响应data，不保存token及上游msg。网络访问、当日披露覆盖、候选重放和定时任务实际启用均需独立验收，代码可运行不等于生产已启用。

白糖中粮历史另支持 `stock-api-cofco-history/1` 来源封套，来源键为
`stockapi_CZCE_SR_cofco_<start YYYYMMDD>_<end YYYYMMDD>`。`fut_basic` 以
`exchange=CZCE,fut_type=1,fut_code=SR,limit=10000` 取得不足上限的完整合约目录；
其 data 保存在 catalogue；`fut_trade_cal` 的 CZCE 日期区间 data 保存在 calendar，
只以实际返回的开市日检查缺报，不把未返回日历日期推断为休市。已知交易日整日未返回
任何白糖报表时生成明确 `report_absent` 空值，图表断线，不插值。筛选上市/到期日与请求区间重叠的所有 `SRYYMM.ZCE` 普通合约，
逐一以四位年月 `symbol=SRYYMM` 调用 `fut_holding`，不是把三位郑商所展示代码或
`symbol=SR` 品种汇总的空响应判作无历史。每份 report 的 windows 完整、连续、无重叠覆盖
封套日期区间；每个 window 按 limit=2000、offset=页号×2000 分页，末页不足上限才完整。
data 只含 fields/items，URL、封套日期、合约、账户、数值与所有原始页须可离线重放。
分页出现重复成员时失败；可重新读取较小的日期窗口验证，不能直接删重后声称完整。

重放只投影中粮席位，保留合约、原始会员名、原始账户、接口明确返回的0和空值；
当日有合约报表而中粮不在返回表内时生成 positions=null、raw_member=null 的明确缺失标记，
不生成推测仓位。此类行标记 `record_type=cofco_contract_history_v1`，没有 rank，

页面独立的“合约榜单可见持仓（历史）”按当日返回合约、所有已披露账户求和，显示合约覆盖；

接口零值也不能证明榜外实际零仓。采集、代码上线与历史数据发布分别验收，
使用现有四板块来源重放和受控增量交付链，不改触发计划，不覆写旧历史版本。

已显式回补过此数据集的国内定时链，在原有 `positions_stock_api=true` 情况下继续读取
中粮单交易日合约数据；没有中粮历史数据的旧安装不自动扩大请求范围。原始排名的
