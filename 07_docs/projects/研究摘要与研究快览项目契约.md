# 研究摘要与研究快览项目契约

## 1. 职责与边界

Summary Engine 是既有业务数据链的只读下游消费者。固定链路为：

```text
stable/runtime 业务数据
→ 事实计算层
→ 规则分类层
→ 结构化 Summary 对象
→ 页面 renderer
```

Engine 不抓取、刷新、修复、promote 或写回天气、国内基差、NASS 等业务数据。页面 renderer 不读取原始表重新计算业务口径；自然语言只能读取结构化事实和分类。

当前 V1 正式启用范围包括：天气 Weather Summary、国内基差 Summary / 最新变化、美豆种植生长 Summary，以及在“研究快览 / 最新变化”页面中只读聚合的美豆出口销售与装船“本周观察”。研究快览当前包含天气、国内基差、美豆种植生长、美豆出口销售与装船四个一级模块。

美豆出口销售与装船不是独立的 FAS/FGIS Summary Engine，也不存在 `summary_engine/exports.py`。研究快览与原出口页面共同复用 `load_current_export_page_payload()` 和 `format_soybean_export_weekly_observation()`，继续读取同一正式 FAS/FGIS stable、Manifest 和 status，不重新计算 FAS/FGIS 业务数据。USDA Summary 属于未来扩展能力，当前 V1 未启用。

## 2. Source of truth

- 天气：当前运行环境中 `WEATHER_DATA_DIR` 指向的正式只读天气目录；未配置时仅为 Windows 本地开发副本。
- 国内基差：当前页面实际读取的 `01_data/database/basis/basis_quotes.parquet` 或明确标识的本地回退文件。
- 美豆种植生长：页面成对选择的正式 progress/condition stable 文件。
- 美豆出口销售与装船：原出口页面读取的正式 FAS/FGIS stable、Manifest 和 status；研究快览只复用同一页面 payload 和确定性周度观察 formatter。

生产 freshness 必须根据生产进程实际读取的 source identity 计算。Windows 本地旧副本只能用于开发、fixture 和受控验证，不能替代生产身份。

## 3. 分层契约

- 事实层：输出数值、单位、日期、比较身份、覆盖率和缺失原因，不输出研究判断。
- 规则层：只消费事实；阈值、分类词、顺序和模板集中在版本化配置。
- Summary 对象：至少保存 schema/module/summary/source/comparison/generated/calculation/rule/freshness/facts/classifications/text/missing 字段。
- renderer：只格式化 Summary；不得读 stable 或重新计算。

相同 source identity、calculation version 和 rule version 必须得到相同事实、分类和文字。`generated_at` 是生成事件身份，不得参与文案或业务分类。

## 4. 更新、失败与新鲜度

V1 不修改现有更新 pipeline，也不物化正式摘要。页面读取时以业务 source identity 生成；identity 未变化时业务结果必须稳定。以后如增加缓存或随 pipeline 物化，必须另行更新本契约。

缺文件、schema 异常、比较期缺失或覆盖不足时按模块降级，保存 `missing_reason`；禁止补零、跨序列比较或推测。一个模块失败不得使其他摘要或研究快览整体崩溃。

新鲜度状态至少区分 `fresh`、`stale`、`missing`、`unknown`。不同模块分别显示自己的业务日期或 release，不得暗示同步更新。

## 5. 规则和可追溯性

规则配置必须有唯一 `rule_version`；事实算法必须有 `calculation_version`。每条摘要可以追溯：

```text
source_dataset/source_identity/source_date
→ facts/comparison_identity
→ calculation_version
→ classifications/rule_version
→ headline/detail_text/short_text/generated_at
```

土墒正式单位为 `%`，深度为 `0-100cm`；V1 未获准定义高低阈值，只输出当前值、五年同期均值和百分点差，分类为 `classification_pending`。

## 6. 页面归属

- 天气、国内基差和美豆种植生长业务页面展示各自已批准的 Summary。
- `spread-dashboard` 新增独立“研究快览 / 最新变化”页面，包含天气、国内基差、美豆种植生长和美豆出口销售与装船四个一级模块；前三者聚合各自 Summary，美豆出口销售与装船复用原页面的确定性“本周观察”。任一模块不可用时单模块降级，不得使整页空白。
- 主工作台首页继续保持静态导航，不展示动态摘要正文。
- 微信群、飞书或其他推送仅作为未来 renderer；V1 不自动推送，统一复用 `short_text`。

## 7. 未来扩展边界

V1 已在研究快览中复用现有美豆出口销售与装船确定性周度观察结果，但未启用独立 FAS/FGIS Summary Engine。若未来批准独立 Summary，必须在独立任务中先核验正式数据身份和跨应用契约，再增加消费者、adapter、规则、测试与页面；不得把当前只读聚合展示描述为独立 Summary Engine。

USDA Summary 当前未启用。未来若重新批准，必须在独立任务中核验正式数据身份和跨应用契约，不得复用未提交的历史试验实现冒充当前能力。

未来 USDA 只读接入如获批准，仍必须固定到 immutable release，设置超时、schema/release 校验和模块级失败降级；禁止新增可写共享目录、读取另一容器临时文件或硬编码公网 IP。月修必须匹配相邻 release、同一 commodity/country/metric/marketing year，且逐指标 artifact unit 优先；无法证明历史身份的字段必须显示不可用，禁止联网临时查询或伪造。

## 8. V1禁止事项

- 不把摘要规则写回任何原始抓取、清洗或 promote pipeline。
- 不使用LLM直接读取原表生成数字或结论。
- 不做基差 roll-adjusted 连续序列。
- 不把 MYS/IDN 展示比例当全国正式产量权重。
- 不用展示型州权重归因全国优良率变化。
- 未来扩展不得混称 FAS sales/exports 与 FGIS inspections，也不得表达未经验证的因果关系。
- 不自动生成“高温胁迫”“需求强劲”“边际转紧/转松”等未配置规则的判断。
