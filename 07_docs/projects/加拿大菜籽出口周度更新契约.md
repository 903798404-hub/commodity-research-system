# 加拿大菜籽出口周度更新契约

## 范围与边界

在 spread-dashboard 既有加拿大菜籽入口增加“周度出口”页签，种植生长保持独立。
首期只监测菜籽，不接价格、菜油、销售承诺、未装船销售或周度目的国。
用户 StatCan 月度进出口 ZIP 保持只读，不拆成周度，不混入 CGC 曲线。
本契约不授予生产部署、定时任务安装、正式 Runtime 或数据写入权限。

## 官方来源与取数

- 现年目录：https://www.grainscanada.gc.ca/en/grain-research/statistics/grain-statistics-weekly/
- 历史目录：https://www.grainscanada.gc.ca/en/grain-research/statistics/grain-statistics-weekly/archived.html
- 来源是 CGC Grain Statistics Weekly 的作物年度 CSV；保留原始字节、SHA256、URL、获取时间。
- 菜籽 grain=Canola；单位 Ktonnes 转为吨，展示万公吨。
- 全国出口 = Terminal Disposition / Export Destinations 的六个港口 +
  Primary Shipment Distribution / Shipment Distribution / Export Destinations。
  不叠加省级分项、Terminal Exports 分等级数据或其他重复出口表。
- Current Week 为当周；Crop Year 为官方累计，累计含修订，禁止用周值累加替代。
- 此口径是 CGC 报告体系，不是 StatCan 全口径海关出口。
- 2026-10-08 只读取数审计：2026/27 第8周，截止2026-09-27，
  Summary!H27=130.7、H29=921.7（千吨）；CSV 分项汇总与其一致。
  此为一次审计实例，不是永久最新日期或上线状态。

## 研究指标与页面

四项顶部指标：当周出口、作物年累计、累计同比、近四周出口同比。
三图：周出口季节性、官方累计季节性、近四周出口合计季节性。
默认展示最近七个已有作物年度，当年红色加粗，去年虚线。
同作物周匹配去年；排序只使用所选年份中同周有效累计值，注明样本数。
四周合计必须在同一作物年内具有连续四个周编号且各周值有效；缺周即空。
作物年度和周编号直接来自 CGC，日期采用日/月/年，不自行按 ISO 周换算。
首页和观察直接显示完整截止日期，不以第几周代替日期。季节性图横轴显示
8月至次年7月的月/日，点位采用各记录真实截止日期的月日，悬停显示完整源日期。
用于跨年度同周比较的CGC作物周保留在后台和下载明细，不改成ISO周或按月日重算同比。
未报告日期的缺周及明确标记源日期异常的点在图上留空，不猜测或修正日期；
异常数值仍保留在原始数据、指标和来源明细中，并在图前提示。
缺失不变成零，不插值、不连接缺口、不向未发布周延长曲线。
本周观察仅陈述已验证的出口快慢，不推导价格、销售或因果关系。

## 数据更新和安全

独立 module_id=canola-exports；目录与 canada_canola 种植数据完全分离。
原始数据 raw/canola_exports，候选 candidates/canola_exports，稳定数据
processed/canola_exports/weekly.json，状态 update_status/canola_exports.json，备份 backups/canola_exports。
稳定 JSON 原子保存数据和来源，不进行两个文件之间的非原子切换。
候选绑定基线 SHA；本地激活有锁、来源重放验证、备份及原子替换。
源下载失败、解析错误、重复字段、意外分项、删周、过时快照均不覆盖稳定数据。
已列周中缺少出口分项时整项留空并记录缺失分项，不将其当作零、不累加剩余分项。
联网更新对缺项查询官方目录已列的同年同周 Excel；只接受封面作物年、周编号、
Summary 的 Canola 列、千吨单位和 Exports / Current Week、To Date 数值均明确的报告。
仅补 CSV 缺失值，保留 CSV 缺项标识、Excel SHA256、URL 和单元格位置并重放验证。
找不到对应报告则继续留空；禁止用累计差分或空白补零。断网 source-file 导入不自动补证。
官方 CSV 日期倒序时保留原始日期并标记 date_quality=non_monotonic_source_date；
图表提示日期待复核，比较仍使用官方作物周编号。禁止未经另一官方来源核实改日期。
每次整年重新解析，修订记录保留旧值、新值与新来源 SHA；数据未变不替换 stable。
页面只读 stable，不联网抓数、不更新任何业务文件。

本地入口 `04_scripts/canola_exports/update_exports.py`：
`init-dev` 只初始化本 feature worktree 的忽略目录；
`prepare --years 7` 首次导入七年；后续 `prepare` 默认检查官方目录最新年度及上一年度；
`activate-local --candidate <候选绝对路径>` 只允许 isolated-dev/fixture。
`update-local` 将准备候选、来源重放校验及本地激活串成一次命令；仍只允许
isolated-dev，不是服务器生产更新入口。首次可用 `update-local --years 7`，
以后默认检查最新两年，保留未下载历史年度；没有数值变化时保持 stable 字节不变。
`--source-file` 配合 `--crop-year` 支持已下载 CSV 的可复现、断网解析。
正式入口为 `04_scripts/automation/run_production_data_delta_windows.py --domain canola_exports`，
必须从获批独立、干净、detached control clone 使用固定 Python `-I -B` 执行。
独立配置和已哈希的真实服务器基线位于 Git 外；默认只生成候选，不连接 SSH、不发布。
只有独立授权后显式使用 `--publish` 才交付受保护服务器发布器；不得拿本地激活绕过授权。
人工确认官网发布后再触发，不安装周更任务、不按固定日期判定官方发布失败。
更新链整次持有非等待锁；联网采集在独立子进程执行，20分钟总超时后终止采集，
不运行网页请求、不下载到正式目录。首次获取配置指定的历史年度数，后续检查最新两年。
来源证据覆盖全部保留年度的 CSV 和被使用的官方 Excel；服务器固定镜像断网重放来源，
复核记录、日期、修订、基线、单位和哈希后备份并发布。任一步未通过不得覆盖旧数据。
配置 `expected_cutoff` 可指定人工确认的截止日期；新数据未达到该日期时停止发布，
由人工核对官网和采集结果。为 null 时仍报告实际 `latest_cutoff`，不得宣称数据必然最新。
NO_CHANGE 仅表示本次来源与已发布业务事实一致，不等于官方已发布下一期，也不等于故障。
结果及服务器回执单独记录检查和发布事实；NO_CHANGE 不修改正式 stable/status 字节。
发布请求失联时不能直接假定服务器未更新，先核对回执和实际基线再决定重试。
当前实现不代表正式配置、policy、镜像、数据或人工入口已在服务器启用。
首次上线前须核对最新 main、正式版本和持仓量主页面改动，纳入首页与消费者回归，
不得用较早菜籽预览基线覆盖持仓量或大豆榨利的新功能。
成功发布后页面读取新数据，不重建镜像、不重启容器；代码发布与数据更新分离。
页面读取缓存最多保留两个数据版本；stable 内容 SHA 改变后自动失效，不依赖人工清空缓存。
