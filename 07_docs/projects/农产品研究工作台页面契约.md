# 农产品研究工作台页面契约

> 文档状态：当前项目专项契约。本文只规定呈现方式，不改变数据、更新、路由、容器或部署规则。

## 1. 适用范围

- 应用：`spread-dashboard`
- 页面：首页、侧边栏、共享展示组件及后续开发的研究图表
- 固定名称：农产品研究工作台

首页是整个研究系统的展开式研究导航，只承担：

- 展开侧边栏的研究信息架构；
- 提供内部页面和外部应用入口；
- 使用简短静态文字说明模块用途、功能集合或地域覆盖。

首页不得计算业务结果、执行更新任务、加载历史明细或展示运行健康状态。数据更新时间、
任务状态、Cron 状态、数据健康、正常/异常和异常提醒统一由“运行监控”承担。

全页面实际数据日期、有限重试和提醒的运行规则见
[`页面业务日期监测与重试契约.md`](页面业务日期监测与重试契约.md)。本页面契约只约束呈现。

### 已验证输入的只读计算复用

网页内部的共享计算服务只复用已经过原读者校验的数据值，覆盖月差、国际价差、汇率、
加拿大菜籽与巴西大豆同期比较、加拿大菜籽出口、仓单、持仓、天气图表以及菜籽、棕榈油、
白糖利润历史图。基差、美豆生长、美豆销售装船及大豆榨利沿用各自已有的版本共享入口。
首页、监控实时状态、外部应用入口与广西/云南已发布天气页面保持各自现有职责。

复用以完整输入内容为键，包括全部行列、类型、索引、缺失与真实零、来源元数据、显式
日期、品种、统计范围、年度和绘图选项；不能抽样识别大型表的历史修订。缓存按原数据
或选项变化失效，各调用者得到独立结果，不能通过修改图表或表格污染其他会话。
仅保留进程内最多256项、序列化结果内容合计最多64MiB、每项最多4MiB的派生结果，另有
有界缓存元数据。按结果内容大小淘汰，避免小型事实挤出整页图表。单次输入超过16MiB或无法序列化时
使用原计算，异常不缓存。页面代码或配置随新镜像生效时进程缓存重新建立。

原源读取、校验、指针检查、人工编辑、CAS与写入授权不进入这一缓存；页面render、
按钮与状态提示逐次执行。不采集、预填或写回数据，不建立后台任务或持久计算副本，
原有13项更新任务和重试预算沿用现有配置。美国、加拿大、巴西及棕榈油旧天气的更新
仍排除；保留其已有历史展示和原缺失提示。独立USDA、Oil World应用不因页面复用而重建。

验收同时验证原值与完整图表、历史修订、空值与零、筛选变化、跨会话隔离、失败恢复、
缓存大小退回及实际页面调用；计算耗时与浏览器整页耗时分别报告，不以健康接口代替测速。

## 2. 单一导航事实源

左侧侧边栏是所有页面中的紧凑型快速导航；首页是同一导航体系的展开页。两者必须读取
同一套导航事实源，并保持分组、名称、目标页面、路由和外部地址变量一致。

首页不得维护独立的“核心研究入口”配置，也不得创建第三套平行导航配置。首页不生成
“工作台首页”自身的卡片，其余研究入口原则上一一对应。

当前信息架构：

| 分类 | 页面或入口 |
|---|---|
| 工作台 | 工作台首页 |
| 市场行情 | 价差动态；国内现货（基差与一口价） |
| 白糖 | 白糖价差；白糖持仓；白糖基差；白糖进口利润（巴西／泰国）；白糖天气（印度／泰国／广西／云南） |
| 周度跟踪 | 美豆周度跟踪 |
| 天气研究 | 大豆天气；菜籽天气；棕榈油天气 |
| 国际供需 | USDA供需平衡；Oil World供需平衡 |
| 研究工具 | 进口大豆榨利；加拿大菜籽进口榨利；棕榈油进口利润；外资与重点席位；运行监控 |

新增数据优先进入现有模块的内部页面、Tab 或筛选。只有形成独立、长期研究体系时才评估
新增导航入口。

「白糖」分组同时在首页研究导航和侧边栏展示，入口顺序为价差、持仓、基差、进口利润、天气。
基差、进口利润、天气及各地区天气直达路由保留。白糖持仓直达原有的白糖板块，
原“外资与重点席位”的多品种筛选继续可用。

“白糖价差”默认纽约原糖月差，展示同交易日期限曲线、03–05、05–07、07–10、
10–次年03的近减远价差（美分/磅）。第二视图为伦敦白糖对纽约原糖升水，
仅展示03、05、10同交割月配对，按白糖美元/吨减原糖美分/磅乘以 10 ÷ 0.45359237 计算。
第三视图在郑糖月差前展示按实际交割月排序的郑糖期限结构，使用同日同源的 SR 合约收盘价，单位为元/吨。月差复用现有计算和数据。外盘季节性按近腿交割年分线，
以距近腿交割月月初的自然日对齐，最多展示最近五个有记录的交割年。
月份和报价单位依据 [ICE纽约原糖](https://www.ice.com/products/23/Sugar-No-11-Futures)
和 [ICE伦敦白糖](https://www.ice.com/products/37089080/White-Sugar-Futures/specs)。

外盘页面只读数据根下的 `processed/sugar_spreads/daily_quotes.csv`，字段依次为
`trade_date,contract,price_type,price,provider,source_url`。具体合约统一为
`SBYYYYMM`（纽约原糖）和 `WYYYYMM`（伦敦白糖），用交易所交易日期；
`close` 表示日收盘，`settlement` 表示日结算。仅同日期、同口径、同来源的两腿计算价差。
页面标注日期、口径、价格来源和覆盖；无有效配对时展示缺口。
郑糖期限结构采用同字段、独立存放的 `processed/sugar_spreads/domestic_curve.csv`，合约为
`SRYYYYMM`，只读取 `close`。最新交易日同一来源有效收盘价不足两个时提示缺口，原有郑糖月差仍可查看。
可用 `04_scripts/prepare_sugar_spread_candidate.py` 读取已经核对的同格式日收盘或结算数据，
用多个 `--input` 合并新增来源数据及上一份候选。
同键异值拒绝并保留原候选。该入口只写当前工作区的独立候选目录。

### 白糖价差本地联合更新

在已有白糖本地预览的独立 worktree 执行 `python 04_scripts/refresh_sugar_spreads_preview.py`。
一次检查郑商所每日行情的具体 SR 收盘价及 Czapp 日报里的纽约原糖和伦敦白糖结算表。
郑糖按北京时间交易日、外盘按伦敦报告日，各自校验日期和口径。默认检查最近 10 个自然日内的工作日，
外盘请求间隔不少于三秒。尚未发布的报告保留原截止日，有新且可核验的数据才追加。
`--lookback` 可扩大本地补录窗口，`--through` 可压低交易日上限。历史有效值保留。

郑糖最新期限结构、郑糖月差数据库和两种外盘价差的输入先在本地候选中一起验证，再原子切换
预览指针。原始响应、来源、校验值和报告结果保存在各候选中。重复运行时跳过已覆盖的报告。
该入口只服务本地预览。

### 白糖价差服务器联合更新

`09_deploy/sugar_spread_server/run.py` 使用保护配置 `sugar-spread-server/1`。
配置固定 `commit`、`tree`、`image_id`、`data_disk_uuid` 和已挂载的 `data_root`，从只读独立源码运行。
北京时间工作日 18:30 及每日 07:45 使用同一个 `market-data-sugar-spreads` 服务。郑糖期限报价
只取郑商所含实际成交的具体合约日收盘，外盘只取 Czapp 同日两市结算表。两个市场分别按北京时间
和伦敦时间确定业务窗口，检查最近十天的工作日，跳过已覆盖日期，源未发布则保留原截止日。
郑糖月差继续读取现有 Public Current 的 domestic-spread 历史，由原 AKShare 任务维护。
原有 15:15 白糖行情归档属于进口利润，使用自身任务和数据口径。

默认只生成隔离候选。主机使用同一固定镜像运行独立无网络重放，逐笔核对批准的基线、原始响应、
及新增报价。正式运行显式 `--publish`，核对当前应用的只读数据挂载与本次基线哈希，原子切换
`processed/sugar_spreads/official-releases/current.json`。页面和更新时间监测使用清单指向的
不可变行情文件。一个来源失败时，已验证的另一市场可独立续接，任务记录部分失败并返回非零。
保留每批原始报告、校验值、上一份指针及运行结果。回滚先停白糖价差 timer，旧页面和原月差
历史继续可读。必要时基于执行证据在同一锁下恢复上一份指针，并保留已取得的行情和证据文件。

安装前核对获批源码、镜像、数据盘与旧任务，先完成隔离候选重放与页面验收，再独立启用批准的
service/timer。用 `systemd-analyze verify` 和 `systemd-analyze calendar` 核查新 unit 与两次触发时间，
记录实际生产采集、正式指针、各市场截止日和下一次触发时间。

白糖进口利润月份主表与 CSV 同时显示“原糖口径”和“原糖价格日期”。最新价不可用时，
同一具体合约的有效已收盘日线以“收盘价”标注实际交易日，不冒充实时价格或官方结算价。
报价最多保留7天；未收盘、错误合约、连续合约及无有效成交的日线不能用于该回退。
历史测算按原记录取价时点判断日线是否已收盘，不能引入当时尚未产生的价格。

价差动态的“价差看板”切换及展示设置位于页面顶部，板块横向排列并在窄屏自然换行。
保留豆系月差、棕榈油与菜系月差和品种间套利，增加国内白糖价差。
国内白糖使用郑商所 SR 的 01–05、05–09、09–01 月差，沿用现有观察窗口、跨年合约
与 A-B／A/B 计算口径；缺少任一组有效历史数据时明确提示，不补零或延用其他品种报价。
配置和页面支持不代表白糖历史数据已经获取或发布。AkShare 精确 SR 合约及人工历史
列的识别可用于后续独立数据更新；Tankan 已验证的取数与完整性范围保持原样。
价差动态最新年度线宽引用共享 `CURRENT_LINE_WIDTH`（3.4），保留当前年度文字标识。
价差动态顶部“研究视图”可切换到仓单季节性，六品种的单位、汇总及数据生命周期见[仓单季节性契约](仓单季节性契约.md)。视图按需加载，不依赖价差数据库是否存在。

## 3. 首页结构

从上到下：

1. 工作台标题和低视觉权重的研究者信息；
2. “研究导航”及按侧边栏信息架构展开的分组卡片；
3. 简洁页脚。

首页不再保留“核心研究入口”“需要关注”“数据状态概览”“最近访问”或“自定义首页”。

顶部保留：

- 主标题：农产品研究工作台；
- 主标题下方左对齐展示：`徐晓冉 · 13305642778 · xx20236@outlook.com`。

首页不展示研究范围副标题，也不展示 `Agricultural Commodities Research`。

个人信息必须弱于主标题，不使用头像、不形成大型个人名片，也不在侧边栏 Logo 区重复姓名。

## 4. 卡片内容

每张卡片只展示：

- 与侧边栏一致的模块名称；
- 一句简短、稳定的研究用途说明；
- 必要的静态“包含”或“覆盖”说明；
- 进入模块的入口。

功能集合型模块使用“包含”，地域集合型模块使用“覆盖”。这些是低视觉权重的研究范围
说明，不得设计成正常/异常状态的彩色 Badge。

首页卡片不得展示：最新业务日、更新时间、自动或每周更新、数据可用、正常/异常、
Cron、刷新状态、外部 API 状态或其他动态运行信息。

静态范围基线：

| 入口 | 静态范围说明 |
|---|---|
| 美豆周度跟踪 | 包含：种植进度 · 生长状况 · 出口销售 · 出口装船 |
| 大豆天气 | 覆盖：美国 · 巴西 · 阿根廷 |
| 菜籽天气 | 覆盖：加拿大 · 澳大利亚 · 欧盟 · 俄罗斯 · 乌克兰 |
| 棕榈油天气 | 覆盖：印度尼西亚 · 马来西亚 |
| 白糖天气 | 覆盖：印度 · 泰国 · 广西 · 云南 |

白糖天气合并原印度、泰国、广西、云南四个侧边栏及首页入口，页内只渲染当前选择的地区，避免同时加载四个页面。印度默认甘蔗并保留棉花切换；四个旧直达路由继续可访问，不再重复列在侧边栏。四地章节统一以单日降雨为首项和新会话默认项，土壤墒情第二，其他原章节依次靠后；广西、云南仍使用各自独立只读服务，需同步其页面代码，不新增采集、端口或服务。

更细的州、省、气象站、区域数量、模型、预测日期和数据状态只在对应模块内部呈现。

## 5. 运行状态边界

运行监控是合法研究工具入口，并应同时出现在侧边栏和首页展开导航中。运行监控现有功能、
数据读取和状态语义不因首页改版而改变。

侧边栏底部现有环境和“应用运行正常”文案不属于本次首页状态清理范围，继续保留。

## 6. 外部应用降级

外部应用地址只能来自既有环境变量。环境变量缺失时：

- 首页和侧边栏继续启动；
- 对应入口显示暂不可用并禁用；
- 其他模块不受影响；
- 不使用 catalog 中的本地示例地址作为生产回退。

## 7. 视觉基线

方向：浅冷灰背景、白色表面、深蓝灰主文字、低饱和辅助色，信息层级优先于装饰。

| 变量 | 基线值 |
|---|---|
| `page_background` | `#F4F6F8` |
| `surface_background` | `#FFFFFF` |
| `surface_border` | `#E3E8EF` |
| `text_primary` | `#172033` |
| `text_secondary` | `#667085` |
| `accent_primary` | `#2457A7` |
| `card_radius` | `12px` |
| `card_shadow` | `0 2px 8px rgba(23, 32, 51, 0.06)` |
| `content_max_width` | `1440px` |
| `section_gap` | `24px` |
| `card_gap` | `16px` |

卡片数量增加后，优先通过清晰分组、响应式列数和适度纵向滚动保持可读性，不得为了减少
滚动过度压缩卡片。禁止大面积渐变、玻璃拟态、霓虹色、闪烁、复杂背景和大量动画。

## 8. 共享组件边界

共享展示组件可以负责页面头部、分区标题、导航卡片、外部入口、空状态、错误降级和图表配色。

不得负责写入数据、执行更新任务、业务计算、改变正式路由、保存个人配置或替代模块数据读取。

## 9. 响应式

- 宽屏：分组内卡片多列排列，优先适配 1920×1080。
- 普通笔记本：自动减少列数，标题、说明和按钮不溢出。
- 窄屏：自然换行，不依赖固定宽度或横向滚动读取主要内容。

## 10. 验收

本地开发阶段至少证明：

1. 正式 `streamlit_app.py` 主入口正常启动；
2. 侧边栏导航保持完整；
3. 首页除“工作台首页”外与侧边栏入口、分组、名称和目标一致；
4. 首页不存在旧六卡契约、需要关注、数据状态概览或动态状态；
5. 研究者信息及静态“包含/覆盖”说明完整；
6. 内部路由可访问，外部地址缺失时正常降级；
7. 笔记本和窄屏无关键内容溢出；
8. 定向测试、约定影响测试、语法检查和 `git diff --check` 通过；
9. 浏览器验收来自真实 Streamlit 主入口，独立 renderer 或 AppTest 不能替代真实主入口验收。

## 11. 图表标准

后续新增图表及涉及样式的开发沿用已确认的国际价差与加拿大进度图配色。共享颜色、线宽和差异单元格样式的唯一代码定义为 [chart_style.py](../../03_src/agri_research_agent/shared/chart_style.py)；页面引用该模块，避免各自复制或重新选择颜色。加拿大进度图是季节进度图的参考实现；本标准只规定呈现，不计算或修改业务数据。

| 角色 | 颜色与样式 |
|---|---|
| 当年／所选对比年份 | `#C1493F` 红色实线，线宽3.4，完全不透明，优先显示于历史曲线上方 |
| 历史年份 | 使用固定年份色，线宽2；季节进度图透明度0.55，使当年更突出 |
| 同期均值 | `#667085` 灰色虚线，线宽2；在图例中写明均值口径 |
| 网格 | `#E1E5E9`，白色绘图区 |
| 高于均值 | 文字 `#A6342B`，底色 `#FCE8E6`，加粗，保留正号 |
