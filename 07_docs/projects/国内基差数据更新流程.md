# 国内基差数据更新流程

> 文档状态：当前项目操作说明。本文只更新业务数据，不授权代码部署。

## 0. Live Domestic Basis 异步更新试点（candidate，未转正）

本节只约束 `pipelines/lutou_domestic_basis.py` 的 live Candidate/Current 链，不把下文历史本地 SQL 导入步骤作为 live FULL DAILY 的来源。共同状态语义见 [异步数据更新合同](异步数据更新合同.md)。

- Required identity 来自 `02_configs/lutou_domestic_basis.yaml` 的 21 个稳定 series，即商品/地区/现货基差映射；日期不是 required identity。Canonical stable key 仍为 series_id + business_date。
- 已有 Current 的 LIVE_LUTOU 部分与有效窗口 Canonical 按稳定键 upsert。未被增量覆盖的旧行整行保留；业务内容不变的重复窗口行也保留旧 provenance。不得把窗口起点当作删除边界。
- Next State 必须覆盖全部 required identities，且 key 集必须等于旧 Current keys 与有效增量 keys 的并集。源记录、Standard、选中的 Canonical groups 的 lineage 独立核验。
- 仍按各日最近未到期合约的源报价 median 建立 Canonical，保留原 source 字段。非现货报价、过期合约及合法远月不入选是既有有据可查的业务过滤，不是漏行。现货数值无法正常化或合约无法解析在新试点中明确 ERROR，不用旧 Current 掩盖。
- 31 自然日 lookback 仍仅用于寻找增量。额外 opt-in `LutouClient.series_inventory` 在同一只读事务中按原始商品/地区做 MAX(date through end) 和窗口 COUNT；不读取历史 Excel、SQL dump 或复制正式数据。该读查询保留既有 EXPLAIN 上限、timeout、只读权限验证，超限 fail closed，不自动放宽。新增聚合查询的真实生产计划/性能尚需只读验收，本轮未连接 provider。
- `source_latest_date` 指该 raw 商品/地区组合（全部 quote types）截至 query end 的最大日期；不是“最新可用现货基差”。Freshness 用 Next State 的合法 Canonical latest。无现货增量但有一口价时必须报告原始最新日期和过滤证据，不能伪称该现货 series 已更新。
- 独立 inventory 有窗口记录而提取/standard/canonical 漏失则 ERROR；source 比 Current 更新但完全落在窗口外则 `NEW_SOURCE_OUTSIDE_WINDOW_REQUIRES_BACKFILL`，停止并要求明确回填范围，不私自扩大读取或用 NO_CHANGE 掩盖。
- 成功/NO_CHANGE/政策停止/refresh 异常均写独立 immutable `async-update-reports/<run_id>/manifest.json`。无法取得来源时日期为 null；异常仍向现有 provider/事务链抛出。Candidate 内保存 `standard.parquet`、`next-state.parquet`、`async-update.json` 及文件哈希；前者明确只是本轮 increment，后者才是完整 next live state。sealed historical segment 的拼接逻辑不变。
- `assemble_domestic_basis_candidate` 是无 I/O 的组装接口。`run_domestic_basis_live(candidate_only=True)` 返回并密封候选，不修改 Current，也不生成 promotion-authorized Canonical；纯 fixture 和 fake adapter 供本地验收，不能声称等同真实生产验收。
- 独立输出 `coverage_status`、`update_status`、`freshness_status`，并按三维分别统计。NO_CHANGE 可以同时 STALE；UPDATED 也可以同时 STALE，freshness 不覆盖 update_status。
- `freshness_policy` 当前 `threshold_approved=false/freshness_threshold=null/stale_is_blocking=false`。业务已批准：真实身份丢失及 mapping/normalization/candidate 损坏 blocking FAIL；UPDATED/NO_CHANGE allowed；STALE non-blocking WARNING。无已批准阈值时 freshness 为 UNASSESSED，记录真实 latest_date、age_days 和 threshold=null，不阻断 refresh/promotion。未实现交易日 calendar，age_business_days=null，不猜 threshold。
- 仓库原 Public freshness 仅校验页面是否跟上 Current；另有 `summary_rules_v1.yaml/freshness_days.basis=7`，由 `summary_engine/basis.py` 对整份摘要的 `data.date.max()` 标记 fresh/stale。原规则保留，不把全局摘要 7 天擅自扩展为逐 series 阈值。未来阈值独立批准；其当前为空不再是数据更新的阻断条件。
- 真正 ERROR 保留原 Current，并继续沿用统一 require-all refresh 的指针回滚；未修改该事务实现。STALE 在 Basis summary 为 WARNING，统一调度器仍采用既有 UPDATED/NO_CHANGE 表示实际是否 promotion（未来迁移另立任务）。直接 promote 仍要求有效 `/2` 三维报告、匹配 policy 和既有来源/文件身份，不因阈值为空而拒绝。

本节是候选实现合同，不授权 commit、push、Approved SHA 调整、真实 refresh/FULL DAILY 或部署。

## 2. 业务口径

- 只保留 `报价类别=现货基差` 且基差非空；基差 0 是有效平水报价。
- 品种映射：大豆油→一豆、菜籽油→三菜、棕榈油→24度、豆粕→豆粕、菜粕→菜粕。
- 近月合约基础分组键：日期、标准品种、地区、报价类型。SQL 原始基差合同月只用于质量审计，不参与分组。
- 四位期货合约解析为 `20YY-MM`，排除缺失、无效及早于业务月份的合约。
- 每组选择未到期合约中月份最早者；不得按报价数量或主力合约选择。
- 只在目标合约内部对有效工厂基差取中位数；更远合约全部排除并计数。
- 正式稳定键为 `date + commodity + region + quote_type + delivery_month + futures_contract`。
- 正式 `delivery_month` 固定为“现货”；不得把 SQL 原始基差合同月直接写入正式字段。
- `cash_price` 和 `futures_price` 不独立聚合，当前 SQL 候选置空；`source_sheet` 保存原始品种追溯。

## 3. 质量门和原子切换

候选必须先在系统临时目录生成，并满足：

- 字段和类型与现有正式 Parquet 一致；
- 最大业务日期符合配置；最新日五个正式品种均有有效目标合约；
- 页面粒度只含一个合约，稳定键无重复；
- 无有效合约而删除的组不超过全部基础组的 1%；
- 缺失、无效、已过期及远月排除记录均有计数；
- SQL 读取前后 SHA-256 一致；同一 SQL 连续生成业务内容一致。

全部通过后，入口先保存旧正式 Parquet 的身份和独立备份，再以同文件系统临时文件原子替换 Parquet 和更新状态。失败时正式 Parquet 保持不变。

## 4. 本地运行与验收

```powershell
python 04_scripts/update_basis_data.py
python 04_scripts/run_local_dashboard.py
```

页面只读取正式 Parquet，不直接读取百兆 SQL。页面“最新日期”取 Parquet 最大业务日期，不使用 SQL mtime 或 `created_at`。

验收必须覆盖五个品种、各地区、“现货”提货月、近月合约隔离、0基差、空值、折线无同日垂直跳线以及现有入口和页面布局不变。

## 5. 停止与恢复

字段不兼容、日期异常、最新日品种被全部删除、不同合约混合、正式提货月不是“现货”、无有效合约组超过1%、SQL哈希变化、测试或页面验收失败时立即停止，不得覆盖正式 Parquet。

恢复来源是切换前记录的旧文件身份及 `01_data/backups/basis/<时间>/basis_quotes.parquet`。数据更新和代码部署相互独立，不得通过部署顺带覆盖运行数据。
