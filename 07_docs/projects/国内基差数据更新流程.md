# 国内基差数据更新流程

> 文档状态：当前项目操作说明。本文只更新业务数据，不授权代码部署。

## 1. 数据身份

正式原始数据：

```text
01_data/manual/榨利表/油脂油料价格.sql
```

只读取 `basis_price` 表。历史 Excel
`01_data/manual/basis/国内现货基差.xlsx` 继续作为只读备份和人工核对资料，程序不得改写，且不再生成正式数据库。

正式数据库：

```text
01_data/database/basis/basis_quotes.parquet
```

正式配置和入口：

```text
02_configs/basis_sql.yaml
04_scripts/update_basis_data.py
```

## 2. 业务口径

- 只保留 `报价类别=现货基差` 且基差非空；基差 0 是有效平水报价。
- 品种映射：大豆油→一豆、菜籽油→三菜、棕榈油→24度、豆粕→豆粕、菜粕→菜粕。
- 近月合约基础分组键：日期、标准品种、地区、报价类型。SQL 原始基差合同月只用于质量审计，不参与分组。
- 四位期货合约解析为 `20YY-MM`，排除缺失、无效及早于业务月份的合约。
- 每组选择未到期合约中月份最早者；不得按报价数量或主力合约选择。
- 只在目标合约内部对有效工厂基差取中位数；更远合约全部排除并计数。
- 正式稳定键为 `date + commodity + region + quote_type + delivery_month + futures_contract`。
- 正式 `delivery_month` 固定为“现货”；不得把 SQL 原始基差合同月直接写入正式字段。
- `cash_price` 和 `futures_price` 不独立聚合，当前 SQL 候选置空；`source_sheet` 保存原始品种追溯。

## 3. 质量门和原子切换

候选必须先在系统临时目录生成，并满足：

- 字段和类型与现有正式 Parquet 一致；
- 最大业务日期符合配置；最新日五个正式品种均有有效目标合约；
- 页面粒度只含一个合约，稳定键无重复；
- 无有效合约而删除的组不超过全部基础组的 1%；
- 缺失、无效、已过期及远月排除记录均有计数；
- SQL 读取前后 SHA-256 一致；同一 SQL 连续生成业务内容一致。

全部通过后，入口先保存旧正式 Parquet 的身份和独立备份，再以同文件系统临时文件原子替换 Parquet 和更新状态。失败时正式 Parquet 保持不变。

## 4. 本地运行与验收

```powershell
python 04_scripts/update_basis_data.py
python 04_scripts/run_local_dashboard.py
```

页面只读取正式 Parquet，不直接读取百兆 SQL。页面“最新日期”取 Parquet 最大业务日期，不使用 SQL mtime 或 `created_at`。

验收必须覆盖五个品种、各地区、“现货”提货月、近月合约隔离、0基差、空值、折线无同日垂直跳线以及现有入口和页面布局不变。

## 5. 停止与恢复

字段不兼容、日期异常、最新日品种被全部删除、不同合约混合、正式提货月不是“现货”、无有效合约组超过1%、SQL哈希变化、测试或页面验收失败时立即停止，不得覆盖正式 Parquet。

恢复来源是切换前记录的旧文件身份及 `01_data/backups/basis/<时间>/basis_quotes.parquet`。数据更新和代码部署相互独立，不得通过部署顺带覆盖运行数据。
