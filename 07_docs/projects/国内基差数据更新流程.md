# 国内基差数据更新流程

> 文档状态：当前项目操作说明。本文只更新业务数据，不授权代码部署。

## 1. 数据身份

人工母版：

```text
01_data/manual/basis/国内现货基差.xlsx
```

正式数据库：

```text
01_data/database/basis/basis_quotes.parquet
```

原则：

- 母版只由人工维护，程序不得主动改写；
- 正式数据库由受控导入流程生成；
- 生产回退文件和测试 fixture 职责分离；
- 数据更新不得改变代码、镜像或容器配置。

## 2. 本地日常流程

1. 在现有 Excel 工作表末尾追加数据。
2. 检查日期、品种、地区、基差和一口价。
3. 确认没有删除或修改历史记录。
4. 在仓库根目录运行：

```powershell
python 04_scripts/run_local_dashboard.py
```

脚本会先导入正式基差数据库，输出最新日期、总行数、品种数和地区数，再启动 Streamlit。

如果导入失败，面板不得启动。不得为了打开页面而跳过导入错误。

## 3. 本地验收

成功标准：

- 正式 Parquet 存在且可读；
- 总行数不减少；
- 最新业务日期符合 Excel；
- 品种和地区数量合理；
- 页面“基差”和“一口价”均能查询新增数据。

## 4. 服务器更新

上传前计算本地 SHA-256：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '01_data\manual\basis\国内现货基差.xlsx'
```

使用已批准的传输工具上传到固定 incoming 路径。上传后在服务器计算 SHA-256，只有两端完全一致才执行：

```bash
docker exec spread-dashboard python /app/04_scripts/update_basis_data.py
```

执行后核验：

- 命令成功；
- 总行数不减少；
- 新增数等于实际新增业务记录；
- 最新业务日期正确；
- 状态 JSON 为成功；
- 页面可查询；
- incoming 入口已清理。

## 5. 失败和恢复

以下情况立即停止：

- 本地和服务器 SHA-256 不同；
- Excel 不存在、损坏或大小异常；
- 历史记录被删除或修改；
- 出现未知品种、关键空值或重复冲突；
- 更新脚本拒绝；
- 稳定 Parquet、状态文件或页面验收不一致。

不得：

- 手工修改 Parquet；
- 用样例数据库覆盖正式数据；
- 连续反复运行失败任务；
- 通过代码部署顺带替换基差数据；
- 删除用户仓库外唯一备份。
