# 油料作物天气研究页面契约

> 文档状态：当前项目专项契约。本文定义油料作物天气模块的长期业务、数据、页面和运行边界；第一阶段仅实现美国大豆研究完整版。本契约不批准自动更新或生产部署。

## 1. 项目目标与目标用户

本项目面向农产品研究人员，在主工作台中提供油料作物天气研究能力。核心研究
目标是判断当前天气相对本地区历史同期的异常程度，并使研究人员能够追溯地区、
指标、作物季、历史基准、预测模型、权重和数据更新时间。

页面应支持：

- 查看观测、历史和预测天气序列；
- 比较当前作物季、上一作物季和历史同期；
- 识别降雨、气温和土壤墒情的阶段性异常；
- 查看地区结果和经过说明的加权汇总；
- 明确区分事实数据、计算结果、预测数据和尚未确认的基准。

不同国家的原始天气绝对值不要求统一到同一水平或同一历史分布，但同一地区、
同一指标的历史序列必须保持来源、单位、清洗、日期对齐和计算口径内部一致。

## 2. 系统归属与容器边界

- 页面归属于主工作台和 `spread-dashboard`，作为内部研究页面运行。

- 页面代码不得硬编码生产 IP、主机名或外部服务地址。
- 页面应复用主工作台的导航、视觉基线、共享状态组件和失败降级语义。
- 内部 Python 模块、函数、类、变量、字段和配置键使用英文；用户页面标题、
  筛选项、指标说明、状态和错误信息使用中文。

两种页面必须：

第一阶段只实现研究完整版，不创建精简版文件、路由或占位入口。

## 7. 数据源适配边界

具体稳定数据源尚未确定。本契约不绑定数据库密码、主机、账号、单一供应商或
单一文件绝对路径。数据源差异必须封装在适配层，页面只消费标准化结果。

适配接口至少输出：

| 字段 | 类型与含义 |
|---|---|
| `date` | 数据所属的本地业务日期，不含未说明的时区转换 |
| `crop` | 英文稳定作物标识；第一阶段为 soybean |
| `country` | 英文稳定国家标识；第一阶段为 United States 的统一代码或枚举 |
| `region` | 英文稳定地区标识；显示名称通过映射提供 |
| `metric` | 英文稳定指标标识 |
| `data_type` | `observed`、`historical`、`forecast` 或契约后续批准的枚举 |
| `model` | 预测模型标识；EC、GFS 等；非模型数据为空 |
| `value` | 数值；不得用 0 代替缺失 |
| `unit` | 明确单位；同一地区同一指标的时间序列必须一致 |
| `source_updated_at` | 带时区的数据源更新时间，不等同于业务日期 |

允许的扩展字段包括：

| 字段 | 含义 |
|---|---|
| `season` | 经作物季规则映射后的稳定季节标识 |
| `normal_value` | 已确认历史基准值；基准未确认时必须为空 |
| `normal_period` | 基准覆盖的明确年份或季节范围 |
| `weight` | 单一配置来源提供的地区原始权重，不代表已经归一化 |
| `forecast_run_at` | 带时区的模型起报时间 |
| `lead_day` | 相对起报时间的预测天数 |
| `data_version` | 可用于缓存失效和审计的数据版本 |

适配层必须完成字段映射、类型检查、单位确认、地区标识规范化和基本重复检查；
作物季、历史基准、累计值和权重汇总属于独立计算层，不得散落在页面组件中。

## 10. 地区和权重

旧项目的 15 州权重只作为第一阶段回归参考，不自动视为永久权威值。进入新实现
前仍需人工确认：

- 15 州清单及地区标识；
- 权重来源；
- 适用年份；
- 权重代表种植面积、产量还是其他口径；
- 覆盖率分母；
- 缺失州和缺失日期的处理门槛。

新实现中权重只能存在于一个受控配置来源。不得同时在 Python、Excel 和页面中
维护三套权重；计算层和页面只能读取该来源。

对参与计算且当日有效的地区集合 \(R\)，加权值必须显式归一化：

```text
normalized_weight_i = raw_weight_i / sum(raw_weight_j for j in R)
weighted_value = sum(normalized_weight_i * value_i for i in R)
```

页面必须同时说明：

- 配置权重覆盖范围；
- 本次实际有数据地区的有效覆盖范围；
- 是否因缺失地区发生重新归一化；
- 原始权重合计和归一化后合计。

不得静默继承旧项目中“88.9%”与实际权重和不一致的问题。分母或权重冲突未解决
时，可以使用经人工批准且清楚标记的临时回归口径，但不得将其命名为永久权威
权重；无法明确临时口径时停止实现加权汇总。

## 11. 作物季与日期对齐

- 作物季起止、季节命名和跨年规则必须来自单一非敏感配置，不得由图表临时推断。
- `date` 表示数据所属日期；`source_updated_at` 和 `forecast_run_at` 不得替代
  业务日期。
- 当前季与上一季必须依据已确认的作物季规则和最新有效观测日期识别，不得只用
  系统当前年份判断。
- 历史序列比较应使用作物季内位置对齐；日历月日、季节日序或周序采用哪一种，
  必须由指标口径明确。
- 跨年季节、闰日、季首季末和不完整季节必须有确定处理和测试。
- 不完整当前季不得被计入“完整历史季节”样本。

美国大豆作物季起止日期和跨年命名仍待人工确认。确认前可以实现可配置映射和
测试样例，不得把猜测日期固化为长期业务规则。

## 12. 历史对比口径

页面逐日“5 年均值”和旧 Excel“30 年历史同期”是两个独立口径，不得混用、
互相补齐或使用相同标签。

- 5 年均值可以依据当前季之前已确认的五个完整季节计算。
- 五季不足、任一季不完整或日期映射不可比时，必须显示样本不足，不得静默缩短
  样本期。
- 参与均值的五个季节标识必须可追溯，并在页面说明或详情中可查看。
- 30 年历史同期的年份范围、数据来源、生成方法和缺失处理未确认前，不得自行
  伪造，也不得命名为已确认的“30 年均值”或“30 年正常值”。
- 第一阶段允许先实现不依赖 30 年基准的图表。
- 如使用旧 Excel 基准，只能作为待核验输入，必须记录文件身份、年份范围和
  生成方法；不能成为不可追溯的永久业务规则。

天气异常应在同一地区、同一指标、同一作物季位置和同一单位下计算。异常可表达
为绝对差、百分比或标准化异常，但具体公式和零分母处理必须在实现前确定并测试。

## 13. EC 和 GFS 预测边界

- EC 和 GFS 预测记录的 `data_type` 为 `forecast`，`model` 必须明确。
- 两个模型独立展示和计算，不得默认平均、拼接或以一个模型静默替代另一个。
- 每个模型应依据 `forecast_run_at` 和 `source_updated_at` 选择经过适配规则确认
  的最新有效批次。
- 预测期限以实际可用数据为准，不外推、不复制最后一个值补齐。
- 历史、观测和预测的分界必须在图表上可识别。
- 模型缺失时可以展示另一模型，但必须说明缺失模型和更新时间。
- 模型数据不能写入历史事实序列；预测过期后只有取得有效观测值才能成为观测。

EC、GFS 的正式来源、起报频率、预报时长、时区和版本选择规则仍待数据源确定后
确认。

## 14. 最新有效日期、缺失、重复和重叠处理

页面必须分别展示：

- 最新有效观测日期；
- 数据源更新时间；
- 各模型起报时间和预测截止日期。

不得把未来预测截止日期显示为“数据更新至”，也不得用文件修改时间冒充业务日期。

标准记录至少以
`date + crop + country + region + metric + data_type + model`
识别业务唯一性；如一个来源允许同键修订，必须增加可追溯的版本或起报字段。

处理规则：

- 完全相同的重复记录可以在适配层去重并记录数量；
- 同键但数值冲突且无法由版本规则解释时必须停止该指标加载；
- 缺失日期保持缺口，不以 0、前值或线性插值静默填充；
- 累计值遇到缺失时必须标记不完整范围，不能把缺失当作零降雨；
- 历史与预测日期重叠时，在“当前接续序列”中有效观测优先，预测从观测之后开始；
- 原始预测仍可按模型独立查看，不得因接续规则被改写或删除；
- 历史样本与当前季重叠、模型批次重叠和多源重叠必须在计算层解决，页面不得靠
  绘图顺序掩盖冲突。

## 15. 缓存和性能

- 每次只加载当前作物、当前国家、当前指标和当前选择地区需要的数据。
- 不得在页面启动时一次性读取全部国家、计算全部组合或生成约 60 张图。
- 数据适配、计算和图表缓存应分层，避免把页面组件对象作为业务事实缓存。
- 缓存键至少包含作物、国家、指标、地区选择和影响结果的计算配置。
- 缓存必须能根据 `data_version`、稳定文件修改时间、来源更新时间或等价的可验证
  数据身份失效。
- 缓存不得掩盖数据源失败、长期返回过期结果或跨用户泄露敏感信息。
- 筛选切换后只能触发新选择所需的读取和计算。

具体缓存期限和可接受加载时间应在实现阶段通过本地测量确定，不在本契约中猜测。

## 16. 失败降级

- 数据源或稳定数据不可用时，天气页面显示清楚的“暂不可用”状态、受影响范围和
  非敏感错误摘要。
- 单一指标、地区或预测模型失败时，其他有效内容继续可用。
- 天气页面失败不得阻断主工作台首页、其他内部页面、USDA 或 Oil World 入口。
- 不得自动回退到旧静态 HTML、旧 Excel 输出、未知缓存或样例数据并伪装为正式
  结果。
- 如使用明确标识的样例或测试 fixture，只能在测试环境中使用，页面必须显示
  非生产数据状态。
- 降级状态应区分数据缺失、口径待确认、来源失败和计算拒绝。

## 17. 敏感信息

数据库密码、Cookie、Token、账号、SSH 密钥和固定生产地址不得进入源码、普通
配置、页面、日志、测试 fixture、截图、契约或 Git 历史。

未来如需认证：

- 凭据只通过环境变量或仓库外受控凭据文件注入；
- 仓库只登记变量名和非敏感配置示例；
- 页面和审计日志只记录脱敏错误；
- 不复用旧浏览器 profile、Cookie 数据库或个人会话；
- 不通过命令参数、URL 查询串或前端代码传递秘密。

## 18. 测试要求

第一阶段至少需要以下自动测试：

1. 作物季日期映射，包括跨年、季首季末和闰日；
2. 当前年/当前季与上一年/上一季识别；
3. 前五个完整季节的选择和逐日均值；
4. 累计降雨在观测与预测边界上的接续；
5. EC、GFS 与历史/观测数据的边界和独立性；
6. 完全重复日期的确定性处理；
7. 冲突重复记录的拒绝；
8. 历史、观测与预测重叠处理；
9. 缺失日期不被静默填零；
