# 坚果云国内基差只读接入

## 来源与写入边界

唯一允许读取的文件是 Windows 本机
`D:\坚果云\123\国内基差及一口价\基差数据.xlsx`，原始工作表为
`油脂油料价格 basis_price`。不读取汇总公式或透视表作为原始报价。

用户指定整个 `D:\坚果云\123` 为禁止写入区域。采集器仅以 rb/read_only 打开
指定文件，不保存工作簿，不刷新外部链接，不改名、不删除、不移动源文件；
候选、锁、日志和转换结果均在外部目录。输出路径经过祖先目录的 symlink/junction
检查，指向 123 的输出在创建目录之前拒绝。此约束没有改变 Windows 文件权限。

文件修改时间不是业务日期。读取前后核验 SHA-256，发生变化即拒绝候选。

## 报价语义

- 现货基差：选择日期、品种、地区内最近未到期的 YYMM 合约，在同一合约内取工厂报价中位数；
  远月基差、已到期及不可解析合约不进入图表，计入审计计数。
- 一口价：取同日同品种同地区现货价中位数，不要求存在基差或期货合约。
- 缺值不填零，不填日期；零基差和负基差均允许。基差报价的现货、期货价保持 NULL，
  避免独立聚合后产生虚假的 cash - futures = basis 关系。
- 品种映射：大豆油→一豆、菜籽油→三菜、棕榈油→24度，豆粕、菜粕保留原名。
- 每条新序列保留源 SHA、工作表、来源组身份、参与行数和剔除远月行数；报告逐序列最新日期。

## 候选生成与历史保护

入口：`04_scripts/update_basis_from_nutstore.py`。

```text
<approved-python> -X utf8 -B 04_scripts/update_basis_from_nutstore.py --baseline-package <verified-local-public-package> --output-root <new-external-candidate-directory>
```

也可用 `--baseline-root <formal-basis-dataset>` 仅准备独立基差 Current。
输出目录必须不存在，与基线隔离，禁止覆盖重复候选。

首次切换从实际正式 Current 的 max_date 之后追加。16,331 条封存历史与全部既有正式
记录逐字段保留，存入候选 baseline.parquet 并核验；不会用新文件覆盖2018年以来的旧历史。
本入口采用追加模式，截止日及之前的补到报价或历史修订需要单独审计，不自动改写。
若文件没有更晚业务日期，数据集模式返回 NO_CHANGE，整包模式拒绝发布空更新。

新 Current 使用 domestic-basis-current/4；旧 /3 读取兼容保留。正式页面读取器验证
新基差与一口价语义，允许新增地区和序列。原 Lutou updater 对 /4 明确停止，避免
旧数据源覆盖已切换的数据。其他 Public Current 与价差 artifact 必须逐文件 SHA 不变。

FULL DAILY 的 Lutou 基差适配器遇到经过验证的 /4 时，在网络连接及查询前报告
SOURCE_UNAVAILABLE（旧来源已退出），保留 Current；不将它当成新源 schema 错误，
也不阻止其他独立来源更新。该适配器仍只报告旧 LIVE_LUTOU 的最后日期，
不把坚果云日期记成 Lutou 日期。整包生成会从经过实际读取器验证的 /4 中补入
nutstore.domestic_basis 最新日期，防止天气等数据更新时丢失文件来源的日期。
FULL DAILY 不读取 Windows 坚果云文件；新报价通过外部只读候选入口单独交付。

## 上线顺序

候选生成不写服务器，不更改定时任务。先完成 exact candidate 的 required CI、
代码发布审批和独立 Candidate 验收，再部署同一镜像；生产数据交付单独批准，绑定
实际旧 Current ID、manifest/artifact SHA，并走现有 CAS、备份和回滚流程。
不得让旧生产镜像提前读取 /4，也不得手工覆盖服务器 current.json。

Windows source 只负责只读文件采集和外部候选准备；服务器只接收验证后的数据包，
不挂载坚果云主文件夹。日后定时接入须固定获批 producer Commit/Tree 与目标 Current，
不能从正在编辑的工作树直接定时发布。

价差定时任务必须另行更新其获批 control clone 的 Commit/Tree，不能仅将代码合入 main
就声称生产更新器已修复。美豆 FAS 与 FGIS 的 stable、status、锁及来源通道继续独立。
