# 外盘日度汇率研究页面契约

## 范围与阶段

应用为现有农产品研究工作台，页面名为“外盘汇率”，放在“市场行情”。首页和侧边栏沿用同一导航事实源。首期完成只读页面、官方数据解析和本地快照预览，不安装定时任务，不发布服务器，不改写现有榨利、持仓或加拿大数据。

| BRL | 巴西白糖、大豆、豆粕、咖啡 | 巴西央行SGS序列1，PTAX卖出参考汇率 |
| CAD | 加拿大菜籽、菜油、小麦 | 欧洲央行每日参考汇率 |
| AUD | 澳大利亚菜籽、小麦、棉花 | 欧洲央行每日参考汇率 |
| MYR | 马来西亚棕榈油 | 欧洲央行每日参考汇率 |
| IDR | 印尼棕榈油 | 欧洲央行每日参考汇率 |
| THB | 泰国白糖、橡胶、稻米 | 欧洲央行每日参考汇率 |

| CNY | 中国商品进口成本背景 | 欧洲央行在岸人民币参考汇率 |

巴西来源：[官方序列说明](https://dadosabertos.bcb.gov.br/dataset/1-taxa-de-cambio---livre---dolar-americano-venda---diario)。其他币种来源：[ECB参考汇率说明与下载](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)。ECB API见[官方示例](https://data.ecb.europa.eu/help/api/data-examples)。汇率驱动说明参考[澳洲央行](https://www.rba.gov.au/education/resources/explainers/drivers-of-the-aud-exchange-rate.html)。

统一存储1美元兑换的本币数额。ECB使用同一业务日的“1欧元兑本币参考价÷1欧元兑美元参考价”换算，不能跨日补分母，不能以ECB的BRL替换BCB序列，不能把CNY当CNH。各来源参考时点与日历不同，不合并成同一盘中时点，不称为市场最后成交价。

## 数据与计算

快照版本为`foreign-fx-daily/1`。顶层保留带时区的`generated_at`、`sources`及`observations`。来源保留provider、URL、采集时间、原始响应SHA-256与换算方法。观察字段为`currency`、ISO业务日`date`、数值`local_per_usd`及`provider`。

唯一键为币种加业务日期。重复、未知币种、来源不匹配、非正/非有限数值、未来日期及身份缺失直接拒绝。每个币种独立按日期排序；缺失保留缺失，不填零或沿用报价。日度涨跌使用相邻有报价日，5日和20日使用各自5/20个报价间隔，不称为自然日变化。

本币相对美元收益为`previous/current-1`。多币种强弱比较使用所选区间内所有币种共同有报价的最早日期作为100起点，指数为`base/current*100`。没有共同报价日时显示不可比较，禁止默用各自不同起点。汇率变化只提供研究背景，不做政策或商品价格的因果归因。

## 读取与预览边界

页面默认只读`01_data/processed/foreign_fx/daily.json`，亦可由显式`FOREIGN_FX_SNAPSHOT_FILE`指定只读快照。没有文件时呈现币种范围，无伪造行情。数据损坏时报告不可用，不影响其他页面。页面不请求外部API、不执行采集或更新。

开发预览入口为`04_scripts/foreign_fx/build_preview.py`，输出固定在该检出自己的`06_outputs/foreign_fx_preview/daily.json`。不提供production/root/output改写参数，不写`01_data`。抓取、解析和覆盖校验全部通过后才原子替换预览文件，失败保留此前有效预览；数据不进入普通Git提交。

自动更新准备入口为`04_scripts/foreign_fx/update_preview.py`，同样只写本检出的`06_outputs/foreign_fx_preview/`，无production/root/output覆盖参数，不安装任务、不连接服务器。`daily.json`是该开发工作区的稳定快照；每次运行在`runs/<run_id>/`保留官方原始响应、候选、校验与修订记录、逐次状态。切换前留存字节相同的`previous.json`恢复副本；同工作区使用独占`update.lock`，不自动删除他人或遗留锁。工作区顶层`status.json`只记录最后一次检查，与稳定文件SHA-256绑定。页面只显示与实际快照匹配的状态；失败或状态缺失不会把旧业务日改成今天。

每次重取2021年以来的官方历史，按业务键比较。任何已发布观察被候选删除、币种缺失或ECB某日七币种覆盖不完整均拒绝；新增与官方历史修订独立计数，修订保留旧值、新值和原始文件身份。所有解析与历史保留检查通过后才切换；无新增/修订时稳定文件逐字节保持不变，只刷新检查状态。单源失败不会单独发布另一来源。此阶段没有正式数据交付或调度权限，开发验证不等于生产自动更新已启用。

约定的正式运行时间为每天北京时间07:00，采集截至当时官方已发布的日度数据；07:30、08:00仅作为失败或确认延迟后的重试窗口。BCB与ECB分别保留业务日，不能将前一自然日机械当成应更新日。正式启用前须在实际运行环境验证接口可用时间、来源日历和迟到判定，并完成受保护的数据交付接线；未完成前不注册生产任务。与美豆修复中的共用交付工具分开开发，统一候选验收和容器发布；代码合入不代表正式数据已经导入。

## 页面与验收

页面包含各币种最新业务日期、汇率与1/5/20报价日的本币涨跌，默认单币种季节性，共同起点的本币强弱比较，来源/计算口径和CSV下载。季节性支持年份选择、汇率水平与年初100指数。今年按上海时区的自然年标识，使用共享粗红线；历史年份使用共享年度颜色和透明度。每年实际月日映射至闰年2000，2月29日独立保留，3月以后不因闰年错位。年初指数以各年首个有报价日为基准，`当日汇率/年初汇率*100`；方向与本币强弱指数相反，页面明确说明。历史月度均值仅使用所选的当年之前的历史年份，先对各年每月的实际报价求均值，再对年份等权平均；各月至少2个年份有报价才显示，参考点位于月中，不含今年，不补缺失，不把图形对齐作为稳定季节规律的证明。引用现有共享图表颜色。参考币种计价差异与出口政策在“数据与研究含义”中说明。

必须核验逆向收益、同日交叉换算、不同日历与共同起点、异常/空数据降级、原导航保持、数据页只读、中文UTF-8、打包闭包及真实Streamlit主入口。首期本地验证与正式服务器验收分别报告。

## 正式交付和定时接线

### 服务器直接更新

正式调度可迁移到 Linux 的独立 `market-data-foreign-fx.service` 和 `.timer`，入口为
`09_deploy/foreign_fx_server/run.py --config <protected-config> --publish --retry-if-needed`，
必须以主机 root、固定 Python `-I -B` 从受保护的获批独立检出执行。
服务器直接访问上述四个官方来源，不访问 Windows、不依赖本机开机、登录、文件同步或 SSH 回传。
模板保留 Asia/Shanghai 每日07:00、07:30、08:00，首窗主更新，后两窗条件重试；
源码中的 `.service.template` 和 `.timer.template` 仅为部署模板，验收后才渲染成独立的主机 unit。
同一 producer 当天已完成 PUBLISHED/NO_CHANGE 后跳过，失败、迟到或漏跑仍可补跑。
Persistent 允许服务器重新上线后补跑错过的窗口，单次期限仍为25分钟。

服务器私有配置为封闭 `foreign-fx-server-config/1`，仅含 schema_version、policy、
policy_sha256、image_id、data_disk_uuid；保存于受保护的 `/etc/market-data/foreign-fx-server/`。
每次核验实际数据盘 UUID、挂载点、RW与剩余容量，缺盘禁止回退写系统盘。
策略只允许 foreign_fx，producer/source clone与执行源码一致，采集和离线重放使用同一
固定 Commit/Tree/Image ID。主机只使用 stdlib，任务不安装依赖、不 build/pull 镜像、不重启网站。

独立运行目录为 `/var/lib/market-data/production-data-automation/foreign-fx/`，跨版本共用非等待
独占域锁。每次在生产分配锁下读取真实基线，复制到本次只读目录；网络采集在一次性非 root、
只读根文件系统、无 capabilities、有限 CPU/内存的容器中执行，只写本次候选和原始响应。
容器无生产数据 RW挂载、无宿主凭据、无公开端口，超时只移除本次唯一采集容器。
随后仍经过原有 stage-upload、receive、断网镜像 validate 和主机 CAS publish；
不新增业务数据写入旁路、不改变官方口径、状态 schema或历史保护。默认不带 --publish 仅生成并校验候选。

每次 result.json 和 foreign-fx-last-run.json 保留服务器执行事实、来源失败细节、离线报告及正式回执。
失败仍仅允许在实际 stable SHA匹配时记录汇率失败状态，失败日志自身错误不能隐藏原错误。
启用迁移必须先完成服务器实际四源采集、候选离线重放、正式交付及页面消费验证，再启用本 timer
并停用对应 Windows 汇率任务；保存原 XML和配置作为恢复来源。只停用汇率项，不删除本机任务，
不改动其他 Windows任务、服务器 cron/timer或三个应用。调度切换与代码接纳、数据发布分别留证。

### Windows 兼容和恢复入口

生产入口使用独立、干净、浅克隆的获批 control clone：
`<approved-python> -I -B -X utf8 04_scripts/automation/run_production_data_delta_windows.py --config <private-foreign-fx-config> --domain foreign_fx --publish`。
默认 candidate-only 不连接服务器；正式 publish 使用固定 foreign_fx 策略、Commit/Tree、publisher SHA、Image ID 和实际运行分配目录。
私有配置使用 foreign-fx-delivery-config/1，只允许该域，不借用或放宽 AkShare、FAS 等域的策略。

正式数据为运行分配内的 `01_data/processed/foreign_fx/daily.json`、`source_evidence.json` 和 `status.json`。
初始化要求三个文件同时缺失，已有正式状态要求三者完整；不接管目录内的其他文件。
每次 publish 在分配锁下，通过受保护的 snapshot-baseline 命令读取当时实际正式基线；原始字节与身份在 Windows 外部运行目录留存。
随后获取官方历史和最新发布参考，生成独立候选。服务器在同一获批镜像内无网络重放原始响应、检查全部历史键保留及修订，再通过 CAS、备份、原子切换和回滚交付。
每天不能继续使用第一次交付前的静态空基线。候选模式使用已经只读导出的、明确 SHA 固定的本地基线。

来源日历以两家央行实际最新发布参考为准，不用“昨天应有报价”推断假日。
BCB 最新报价使用官网 JSON 入口 `https://www.bcb.gov.br/api/servico/sitebcb/indicadorCambio`，只接受 `moeda=Dólar` 且 `tipoCotacao=Fechamento` 的唯一收盘记录。带时区的 `dataIndicador` 转换到 `America/Sao_Paulo` 得到业务日期，`valorVenda` 为美元卖出价，两者必须与 SGS1 历史末条一致；不使用欧元、买入价或中间报价。保留 HTTPS 证书验证和直连约束，不跟随跳转到其他入口。
原 PTAX HTML 入口只允许离线重放已经归档的来源证据，不再发起网络请求；原正式历史和来源文件不因此改写。既有证据保持 v1，在获批校验镜像中按精确 URL 选择解析器。
ECB `https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml` 的七币种同日交叉结果，必须与完整历史末条一致。
两家的日期分别保留，参考发布与历史尚未一致时拒绝候选并进入条件重试。四份原始响应均保留压缩原始字节、固定官方 URL、SHA 和字节长度，在镜像内重放时有解压上限。

日常交付使用 `collect_incremental`：初始化保留从2021年的完整采集，已有基线先重放旧
来源证据，再从各币种最早末条向前14天查询新窗口。BCB 使用日期参数，ECB 在覆盖允许
时读取官方90天 XML，缺口更长时读取完整 XML；跨月核对完整历史，或由调用方显式要求
reconcile。月度完整核对压平本期窗口归档，但不删除业务历史、旧快照或恢复来源。
新窗口不得遗漏覆盖区间内原先存在的键，ECB 每日币种必须完整，末条仍与两个官方最新
发布参考一致。失败或 NO_CHANGE 不替换正式报价、证据或成功进度。

SGS 历史通道失败时，已有、已重放验证的基线允许使用巴西央行
`olinda.bcb.gov.br/olinda/servico/PTAX/versao/v1/odata/CotacaoDolarPeriodo` 作为同一美元
PTAX每日收盘卖出价的官方备用采集通道。只读 `cotacaoVenda`，拒绝其他币种、中间公告、
分页/达到上限的响应、重复日、超范围日期及无效值。备用通道必须完整覆盖请求窗口内
全部已发布BRL日期且每个旧值完全一致，否则停止并保留原数据；没有基线的初始化不能
使用此备用。每次仍以网站最新美元 `Fechamento` 参考独立核对最终日期和值。
`BCB_SGS1` 保留为兼容的逻辑序列标识；实际采集通道以每段原始证据的准确URL及SHA为准，
不将PTAX响应伪装成SGS JSON。SGS失败原文、失败摘要、PTAX原文、逐日一致性检查数量
独立保留在本次候选原始资料目录；新旧两种通道均在固定镜像中断网重放。跨月全历史
核对也须逐项匹配全部原BRL记录。未发生业务变化时仍保持正式历史与来源证据原字节，
不以备用来源检查时间冒充新增行情。

快照仍为 foreign-fx-daily/1；增量来源证据使用 foreign-fx-source-evidence/2，平铺保留
从 START 到 request_end 的原始响应段及最新参考，不嵌套复制旧快照。段日期、每段 URL/
字节 SHA/长度、重叠合并和最新参考在断网镜像中全量重放。sources.raw_sha256 在 v2
表示该 provider 原始响应段清单的 canonical SHA，单段原始文件 SHA 保留在 evidence；
不能将它误称为一个最新响应文件的 SHA。旧 v1 证据继续完整重放，转换仅发生在独立
候选中。逐次来源窗口数与本次原始响应字节数写入采集结果，不进入行情业务键。

NO_CHANGE 不改写 daily.json 或 source_evidence.json，只更新与真实 stable SHA 绑定的检查状态。
采集或验证失败保留原报价；有明确基线时可经受保护的 record-check-failure 记录失败状态。
该命令只允许 foreign_fx，并再次核验报价 SHA 未变；若传输结果不明而数据已经成功更新，失败记录不能覆盖新快照的有效状态。

外部运行目录的逐次 `result.json` 和 `foreign-fx-last-run.json` 记录失败阶段、错误类型、经过脱敏且限制长度的消息；网络失败额外记录固定官方 URL、HTTP 状态（如有）及 SSL/超时原因。失败状态记录本身出错时单独保留对应诊断，不覆盖主错误。不保存响应正文、凭据或无界堆栈，其他域和正式状态 schema 不随本修复改变。

任务注册入口为 `04_scripts/foreign_fx/register_scheduled_task.ps1 -ConfigPath <config> -Install`。
没有 -Install 时仅生成外部 XML 供审查，不注册任务。正式安装先核验获批独立 control clone 和配置；Windows 时区必须为 China Standard Time。

都调用隐藏的 launch_scheduled.ps1 和 --retry-if-needed，当天同一 producer 已完成 PUBLISHED/NO_CHANGE 后跳过，其余窗口仅作失败/迟到或首窗口未执行后的补跑。
