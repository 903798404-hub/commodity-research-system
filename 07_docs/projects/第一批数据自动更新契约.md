### 日常增量计算、断更恢复与月分区

普通 AKShare 更新先比较精确 DAILY_CLOSE 的合约/日期键，只计算配置依赖闭包中的日期
和价差组合；未受影响的历史行整行保留。无新增依赖时不重新写价差输出。显式全历史
核对与历史 reconciliation 继续使用原计算器和精确历史允许键，不借增量改造放宽门禁。
已知合约的缺口从各自最后成功日期后补齐，附带两天重叠；不再被新合约七天初始化窗口
截断。新合约仍只初始化最近七天，不宣称已自动获得上市以来全部历史。
国内已实现的 CZCE 持仓按各板块最后正式日期继续，单次最多31自然日，已有日期及周末
由原采集器跳过。进度来自实际正式记录，失败不会把游标推进到目标日；未公开日期保持
未知，不补零。其他未实现的 DCE/FCPO 范围不因此扩张。

服务器 AKShare 私有配置可显式增加布尔 `partitioned_public_packages`，默认不启用；
其他 job 不允许该字段。启用后生成 `public-current-production-package/3`，国内价差
artifact 使用同名 `.parquet` 目录内的 `part-YYYY-MM-<SHA>.parquet`，数据仍有完整历史。
每月文件内容寻址，稳定物理 schema 中未披露合约身份为 NULL；无变化月份复用只读对象。
v3 交付身份额外绑定 MONTHLY_PARQUET 布局，避免与同业务内容的 v2 包发生 ID 冲突。
旧 v2 单文件包继续读取、校验及回滚，manifest 和原版本不就地迁移。
本次 worker 的对象缓存只在所有对象均与已保留候选分区 SHA 相同后清理；未知文件、损坏
对象或额外硬链接直接拒绝，候选本身及失败证据保留。服务器旧版本的相同分区仍交给
既有宿主维护规则合并；当前/回滚独立副本、唯一历史及回滚镜像继续保留。

开启 v3 前必须协调更新应用读者、实际 UID 可读性门禁、Windows 基差与价差生产者、
发布校验镜像和宿主维护工具及其 hash-bound 配置，并完成 v2/v3 双读与旧数据包回滚。
仅代码开发或 CI PASS 不代表已经切换该配置。整个公共包仍按完整 manifest 校验和交付，
本实现不是只发送网络差分；不宣称已消除所有传输、临时复制或真实新增历史的空间成本。
逐次 collection metrics 记录请求/跳过合约、新增/重复价格行、实际计算行数、包字节/
文件数和格式、正式历史行数；未观测的网络字节不得记成零或推算为实测流量。
服务器回执同时记录已核验数据盘在更新前后的实际占用及净变化；这是共享数据盘的
同期变化，可能包含其他任务写入，不能全部归因于本次采集。挂载校验或测量失败时
明确记为 `UNAVAILABLE` / `null`，不假报零增长，也不改变原有发布门禁。

服务器公共行情先执行独立网络预检：受保护宿主只把已校验的价格基线通过 stdin 传给
无特权 worker，在内存读取，不先落盘完整基线、工作簿备份或公共候选包。预检保留
实际来源响应及追加行证明；按完整合约、真实业务日期核对新增行及历史冲突。
接口正常但目标日缺合约时记录 `WAITING_FOR_SOURCE`，请求失败或历史修订仍失败；
两者均不复制完整包、不推进正式基线。每日工作日 16:30、18:30、22:30 检查同一业务日。
无新增行时只核验保留的 Current 字节、CAS 和实际应用读者，返回 `NO_CHANGE`；
不创建 incoming、完整候选包或新 continuation。只有完整且存在新增行，才复制固定
基线到隔离工作区，由断网 worker 重放追加证明、计算依赖闭包并执行历史差异门禁。
原始历史、来源证据、正式旧版本与回滚资产保留；若仅价格续接而价差业务内容不变，
只保存续接文件，不生成公共包。需在非交易日手动重试时，可显式指定公共任务的
`--business-date YYYY-MM-DD`，禁止未来日期和其他任务使用该覆盖；不自动回退目标日。

Public Current 的既有 transport owner UID/GID 固定在受保护配置中，快照核验实际 owner；
正式 publisher 继续用该非 root 账户运行，保持坚果云基差原有读写权限。仅新建 upload 的
ownership/ACL 可以封存，不改变既有 store、release、pointer 或运行账户权限。

每次持久 result/last-run 包含 server host、job、producer、采集结果、校验/回执和脱敏失败阶段。
NO_CHANGE 不代表新业务日；PARTIAL_FAILURE 不接受为全量验收。切换前每项须真实服务器
采集、候选校验、首次正式发布或 NO_CHANGE 回执、正式消费者验证通过；未通过项保留
原 Windows 任务。保存每个原 XML/配置和服务器恢复记录，只禁用对应已验收任务，不删除。
坚果云基差、汇率 timer、其他 cron/unit、应用容器、CNF/历史和人工文件保持原样。

## 正式续接和共享 Current

CGC/持仓每次正式执行通过受保护 `snapshot-baseline` 在 allocation 锁内只读取得固定域文件，
验证 policy、producer、image、SHA/大小、完整性和传输边界；不复用上次已过时的 baseline。
仅允许 foreign_fx、canola_exports、commodity_positions 固定域快照；不接受任意文件列表。
随后复用既有候选 → stage-upload → receive → 固定镜像断网来源重放 → publish 和回读回执。
数据与状态的无变化处理沿用原合同，NO_CHANGE 不假装新增业务日期。

基差读取当前服务器不可变公共包的精确 manifest 和列出的文件，逐文件核验 SHA，
复制前后 Current pointer 一致；包校验和实际消费者校验失败不发布。
与获批本地不可变基线完全匹配的文件只读复用，复制前后核验字节身份；源输入不写入。
新文件才从服务器下载，按文件大小设置 180–1200 秒上限，基线复制总预算 45 分钟。
本地基线损坏、源身份变化或总预算耗尽时停止，不能用未验证缓存或放宽 CAS 继续发布。
只替换基差 dataset；历史逐字段保留，价差 artifact 和其他公共 dataset 身份保持一致。
与既有价差任务使用同一 FULL DAILY 锁；候选公共包留在该任务现有认可的
`<full-daily-lock-parent>/runs/<唯一运行>/runtime/public-data-packages/<package_id>` 外部缓存，
使既有价差任务能够发现新 Current。缓存经完整 package 校验，不改动既有价差任务。
正式切换始终绑定旧 Current ID、manifest SHA、价差 artifact SHA，以及新包身份走 CAS；
Current 已移动则失败，下次重新读取，不强推旧候选。scope evidence SHA 复用 transport
`reconciliation-manifest-sha256` 字段记入回执，语义为基差追加及其他域不变的范围证据。

## 任务安装和验收

`register_first_batch_scheduled.ps1 -ConfigPath <配置>` 仅生成任务 XML；加 `-Install` 才注册。
安装前执行 pinned clone/config 预检，限定 China Standard Time；已有同名任务先导出 XML 备份。
任务以 LeastPrivilege、InteractiveToken、隐藏窗口、IgnoreNew、StartWhenAvailable 运行，最长 90 分钟。
它们依赖 Windows 在线且用户已登录；本合同不存储 Windows 密码、不扩大账户权限。
每个域外部独占锁；两个持仓任务共享同域锁。不抢占遗留锁，不启动并行同域 worker。

每次候选/正式运行记录 result.json 和独立 last-run：检查时间、producer、状态、实际 published、
来源尝试和正式回执；失败仍保留日志和旧正式数据。退出 0 可能为 NO_CHANGE，不等于有新数据。
自动上线验收须分别验证本机任务定义/下次时间、真实采集候选、主机固定镜像重放、
首次正式回执和正式消费者；代码/CI 成功不能替代任务安装与计划运行验收。
生产任务、policy 和数据交付以获批精确安装清单为准。既有任务、容器和运行目录保持原样。
新 policy 安装必须同时建立其独立 incoming、candidate、evidence、backup 目录，
只新增 root 所有的受保护目录，不修改旧目录权限；缺失时 publisher 会拒绝交付。
服务器 Python 调用同时使用 `-I -B`，publisher 自身也禁止生成字节码，避免导入业务模块
在固定源码检出内写入 `__pycache__` 而触发完整性拒绝；源码保护检查不能绕过。
无输入负载的子命令明确关闭标准输入，避免 Windows 任务环境下 OpenSSH 等待继承的
控制台输入；传送 JSON 或二进制负载的命令仍使用独立输入管道，逐字节传输不变。

回滚：禁用本批四个独立任务，保留外部状态/候选/证据；恢复此前同名任务 XML（如有）。
公共包和持仓/CGC 使用原有备份与回滚入口，不删除已验证历史，不改坚果云文件。

### 获授权的宿主镜像与中间副本保留

`04_scripts/maintenance/runtime_retention.py` 是独立宿主维护入口，安装和清理需明确授权。
它不采集、不发布数据、不更换应用容器，也不删除正式历史、备份目录或未解决的失败任务。
既有公共发布包维护保持独立；本工具不把 Docker 的 reclaimable 数字当成可删除许可。

应用镜像把每次变化的 Commit/Tree、构建时间、release labels 和环境身份放在所有依赖
安装及源码复制之后；身份字段完整保留，依赖锁变化仍重建依赖，普通代码变化复用依赖层。
正式构建入口不再无条件传入 `--no-cache`；精确源码输入、基础镜像 digest、最终镜像
源码字节及身份检查保持执行，缓存命中不能替代这些验证。

镜像清理由 root 所有、SHA 绑定的配置列出完整 image ID、已验收且被替代的理由及证据
文件 SHA。每次执行重新保护所有容器（含停止容器）、服务器采集器配置和显式回滚 pins。
未登记的新镜像不会自动删除；新一轮发布必须更新引用审计和退休清单。禁止 prune/force。
失败、未验收及仍被发布恢复链必需引用的镜像不进入退休清单。

成功更新的 baseline、collection/package、collection/bundle、collection/collection、
upload、incoming、candidate 副本至少保留
3 天，且每个 job 保留最近两次成功任务。仅 PUBLISHED/SYNCED 或明确 NO_CHANGE、采集
PASS 的终态回执参与；缺回执、未知状态及未解决失败/候选任务保留。
回执、原始备份、正式运行数据、静态初始基线和 runtime-validation 不在删除范围内。

国内/外盘持仓的 FAIL、PARTIAL_FAILURE 或 CANDIDATE 工作副本，在后续成功任务证明
替代关系后可提前进入可恢复归档，不改写原回执的失败/候选状态。替代证明必须同时满足：
同一 job、完全一致的 producer、采集 PASS、完全一致且非空的来源尝试（含日期/来源、
状态和行数）、没有失败来源或历史修订、旧任务新增分区是成功任务新增分区的子集。
仅按任务名、时间先后或较新的 latest_date 不足以证明替代；无结构化覆盖证据的其他
job 仍保留。成功替代任务按正常最近两次/3天规则保留，归档索引绑定双方回执哈希，
复制前和移除前重验；挂载、静态 pins 和采集锁仍然生效。原始来源、工作副本和独有
文件全部写入去重对象库后才能移除未压缩副本；不以“已替代”为由丢弃独有证据。

采集增量与发布副本体积是两个指标：国内持仓补近期缺日；外盘年度来源可能重复下载
年度文件后只接纳新增记录。合并完整历史后的档案、候选视图和传输包仍可能是全量，
NO_CHANGE 也可能已创建这些工作文件。归档控制留存，不宣称它已把下载或传输改为增量。

过期文件先进入内容 SHA-256 寻址的 gzip 对象库，相同文件只存一份。保存原路径、大小、
哈希、文件权限、所有者及修改时间的恢复索引；完整解压哈希通过、对象及索引持久化后
才能逐文件移除中间副本。历史和来源证据始终可恢复，对象库不自动过期。保留真实新增
历史仍需要空间，不能承诺磁盘永不增长。恢复只允许写新的隔离目录，不覆盖正式数据。

维护使用实际采集互斥锁、数据盘 UUID、挂载引用及逐项重校验；拒绝符号链接、特殊文件、
额外硬链接、敏感文件或过期计划。无候选时保持不变；失败记录回执，不能记作成功清理。
每日北京时间 04:20 的 timer 使用受保护配置，记录实际可用字节变化、归档索引和删除
镜像 ID。停用 timer 即停止后续清理；已有压缩归档通过恢复索引校验还原。

### 服务器持仓增量采集与传输

服务器 positions_domestic / positions_foreign 使用 `commodity-positions-increment/1`：
绑定当前完整档案的 canonical SHA，只携带新增完整报告分区、必要发布元数据与新增来源对象。
来源对象按内容 SHA 去重，大豆与棕油共享的大商所响应只传一次。基线旧行逐字段保留；
同报告分区业务值变化停止，不自动覆盖。国内从实际最新披露续接，已有完整 M/Y/P 汇总日
跳过请求，断更恢复每批最多 31 天；更早历史缺口仍需显式补采。
外盘年度文件日常只刷新当前年，年初 35 天同时检查上一年以接纳延迟报告；更早年份留在历史中。
范围之外的历史校验与回补另行显式运行，
不能把年度来源下载称为按行网络增量。

采集器只读挂载精确的正式档案文件，基线目录仅放空挂载点及小型状态/请求，不复制历史档案。
收集在内存中合并及验证，不写 collection/collection 或 collection/bundle。
NO_CHANGE 仅产生空 updates/objects、绑定基线 SHA 的小型证明，仍通过原有独立断网验证、
来源重放和发布 CAS，不以网络采集器自己的声明跳过校验；来源失败继续标为 PARTIAL_FAILURE。
增量包只有通过独立校验才可发布；基线变化拒绝，未知字段、篡改、缺来源、旧分区重写均拒绝。

发布时才生成一次兼容现有页面的完整 current 档案及更新板块视图。旧 raw、release、
backup 和 displaced 版本继续保留；本改造不清理或重写历史，不把这些恢复资产算作增量包。
它消除采集/上传/接收/候选各阶段的完整档案副本，不声称正式存储已完成全面分区迁移。
旧完整 archive/1 导入和现有 Windows 手动 bundle 交付继续兼容。
正式启用必须验证镜像内新版 codec、主机 publisher 和 worker 为同一获批版本，不能只替换采集器。

### 公共行情和价差的分区增量发布

服务器 AkShare 任务可显式启用 `incremental_public_packages=true`，并绑定已有公共包维护
任务的受保护 `public_object_pool`。先完成来源完整性预检；无变化或缺当日行情时不创建包。
有新增时只读挂载精确 Public Current，基线工作目录不复制其他公共域和历史月分区。
`public-current-increment/1` 仅包含变化月份的 Parquet、完整逻辑清单和旧清单 SHA；
不在采集器中创建完整公共包或月缓存副本。仍保留价格/Excel 续接文件，不能把它称为
全系统逐行存储。源接口返回历史范围与本地增量接纳是两回事。

固定镜像断网重验新增负载、路径、SHA、月份、业务公式及所有历史行/来源字段。
非价差域清单必须完全相等。历史修订、缺失分区、旧 Current 变化或额外文件均拒绝。
正式发布在原宿主采集/维护互斥锁内复用 root 所有、只读、内容寻址的已有维护对象库。
对象不存在时先独立复制并验 SHA，再创建正式版本目录项；已有对象只验读，不 chmod、
chown 或改 ACL。清单仍为兼容的 v3，页面、基差发布器、原子 Current 和回滚接口不变。
每版拥有完整路径清单，但相同文件不重复存放字节。初次接入对象库可能需要补齐旧对象，
必须单独报告实际新对象字节；不得声称首次接入也只占新业务行大小。

可写候选验证仍使用独立普通字节副本，不共享生产 inode。候选验收副本与正式只读对象
引用分别记账；正式日常运行不生成完整候选复制包。正式对象库不自动过期，现有历史
版本和来源证据不删除，维护工具识别同一对象库的既有共享文件。实际空间以 df 及回执为准。
读写权限、实际应用读者、CAS、切换失败回滚和旧版本哈希继续验收。
回退旧采集器前先将 Current 恢复到对应保留的旧版本，再恢复旧配置和 unit；
新对象和版本保留，回退不删除数据，也不要求旧采集器理解新对象所有权。

### 坚果云基差的复制前预检

正式任务先读取服务端 Current、公共清单及其中 SHA 绑定的基差 release 元数据，再以真实截止日期检查只读工作簿。没有新增日期时复核工作簿 SHA、服务端 Current 和清单身份，直接记录 NO_CHANGE，不下载或复制完整公共基线，不生成完整候选包。元数据缺失、日期不一致或 Current 移动均停止；有新增时仍进入完整数据校验和 CAS 发布。工作簿及历史封存文件不修改。

Windows 封存候选时，仅可临时调整所有链接均位于本候选内的私有文件只读属性以执行 fsync，随后恢复原属性；不得调整具有外部链接的共享 inode 或原始历史输入。只读历史复制文件必须通过封存与输入字节、权限不变测试；无法安全清理的失败候选保留并记录恢复路径，不通过修改外部属性来强行清理。
