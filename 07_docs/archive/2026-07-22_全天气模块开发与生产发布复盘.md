## 4. 为什么流程较慢

必要安全成本包括完整 SHA 可信检出与 fsck、候选镜像/数据/路由验收、生产配置
三层审计、逐文件 SHA、原子切换、同一 Image ID 晋级、相邻服务不变性和结果密封。
这些门槛保护了生产，不应删除。

可以消除的成本主要是：真实主入口和运行进程身份发现过晚；`candidate-data` 被提前
清理后恢复；Compose/env 分开审计和同步；把静态 `build:` 误判为实际构建；重复
一次性脚本缺少参数、dry-run 和 finally 证据自检。优化方向是把门槛前移、合并身份
事务并自动产证，而不是放松停止条件。

## 5. P11 不确定性

b02 首次候选存在密封身份不一致。现有材料对具体首次触发字段的描述不完全一致，
因此“是否由构建日期和 Release 日期不一致直接触发”保持待确认，不写成确定事实。
最终流程通过候选启动前完整 seal preflight 解决：同时核验不可变标签、Image ID、
OCI revision、Git Commit、Git Tree 和 Release 元数据；任一不一致即停止，旧候选结果
保持不可变。

## 9. ChatGPT 审核后的四项修正

1. `deployment_plan` 同时锁定当前生产基线和目标 Release；生成计划不要求生产
   Compose/env 已经等于目标。
2. Compose 与 env 一次性审计、预演、纳入计划，并在正式部署事务中联合同步和回滚。
3. Compose 可保留静态 `build:`；门槛检查真实执行 argv，正式切换必须包含
   `--no-build --pull never --no-deps --force-recreate` 且只指定目标服务。
4. 核心 execution argv 直接进入 `deployment_plan` Schema；参数变化必须重建计划及
   Manifest，不再使用计划密封后的独立 amendment 改写安全参数。
