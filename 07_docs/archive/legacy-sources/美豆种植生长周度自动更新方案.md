# 美豆种植生长周度自动更新方案

## 本地入口

```bash
python 04_scripts/soybean_crop_progress/update_soybeans_crop_weekly.py --dry-run
python 04_scripts/soybean_crop_progress/update_soybeans_crop_weekly.py
python 04_scripts/soybean_crop_progress/update_soybeans_crop_weekly.py \
  --git-head 0123456789abcdef0123456789abcdef01234567
```

- 程序按 `America/New_York` 日期自动选择当前年度。
- 正常检查季为每年 4 月 1 日至 11 月 30 日；季外返回 `out_of_season`。
- `--force` 可在季外人工强制运行。
- `--dry-run` 可以调用真实 API 并生成 Raw、Manifest、候选文件和临时审计，但不会替换稳定 Processed，也不会修改固定状态文件。
- API Key 只从环境变量 `NASS_API_KEY` 读取。
- Git 提交解析优先级固定为：命令行 `--git-head`、环境变量
  `MARKET_DATA_GIT_HEAD`、当前工作目录执行 `git rev-parse HEAD`。
- 命令行和环境变量一旦存在就必须是 40 位十六进制提交哈希；无有效外部提交号且
  Git 命令不可用、当前目录不是 Git 仓库或命令失败时，程序在请求 USDA API 前以
  “无法确定部署Git提交，未调用USDA API。”安全失败，不使用 `UNKNOWN`、空字符串或
  伪造值继续运行。
- 最终解析的同一提交号写入 Raw Manifest、JSON/Markdown 审计、固定状态文件和运行日志。

## 数据与运行文件

- 稳定 Progress：`01_data/processed/soybean_crop_progress/soybeans_crop_progress_weekly.parquet`
- 稳定 Condition：`01_data/processed/soybean_crop_progress/soybeans_crop_condition_weekly.parquet`
- 首次上线基线：同目录现有两个 `*_2021_2026.parquet`
- Raw 与 Manifest：`01_data/raw/soybean_crop_progress/`
- 候选文件：`01_data/candidates/soybean_crop_progress/<run_id>/`
- 备份：`01_data/backups/soybean_crop_progress/<UTC时间>/`
- 固定状态：`01_data/update_status/soybean_crop_progress.json`
- JSON/Markdown 审计：`06_outputs/audits/soybean_crop_progress/updates/`
- Dry-run 审计：`06_outputs/audits/soybean_crop_progress/dry_runs/`
- 日志：`10_logs/soybean_crop_progress/`

页面把实际读取文件的 mtime 放入 Streamlit 缓存键。稳定文件创建或更新后，下一次页面访问会自动失效并读取新文件，不需要重启容器。

## 合并与发布

每次只请求当前年度的 `PROGRESS/CONDITION × NATIONAL/STATE` 四组数据。程序保留基线中当前年度以前的所有行，删除旧的当前年度行，再用本次完整的当前年度标准化结果替换。该方式同时捕捉新增周次、当年历史修正、新指标和新州记录，不执行插值、补零、前向或后向填充。

两个候选 Parquet 全部写入并通过质量校验后，才复制到正式目录中的临时文件。临时文件再次校验 SHA-256 和可读性后依次切换。若任一切换或切换后校验失败，程序从同批备份恢复两个旧文件；首次初始化时则删除本次已安装的新文件，避免 Progress 与 Condition 来自不同批次。

## 服务器运行包装脚本

生产容器不安装也不依赖 Git。宿主机包装脚本位于：

```text
/home/ubuntu/market-data/09_deploy/soybean_crop_progress/run_soybean_crop_weekly_update.sh
```

包装脚本固定执行以下流程：

1. 检查正式仓库 `/home/ubuntu/market-data` 和所需宿主机命令。
2. 使用 `/run/lock/soybean_crop_progress_update.lock` 的非阻塞 `flock`
   防止重复执行。
3. 非执行式读取仓库外
   `/home/ubuntu/.config/market-data/nass.env`，要求其中恰好有一个非空
   `NASS_API_KEY`。密钥文件保持 `ubuntu:ubuntu`、权限 `600`，不进入 Git。
4. 在宿主机正式仓库执行 `git rev-parse HEAD` 并严格验证 40 位十六进制哈希。
5. 确认 `spread-dashboard` 正在运行。
6. 临时导出 `NASS_API_KEY` 和 `MARKET_DATA_GIT_HEAD`，执行容器内正式入口，
   原样返回 `docker exec` 的退出码，结束时 `unset` 两个变量。

此前已通过服务器 Docker 26.1.3 的 `docker exec --help` 只读确认其支持
`--env list`。最终调用使用：

```bash
docker exec \
  --env NASS_API_KEY \
  --env MARKET_DATA_GIT_HEAD \
  spread-dashboard \
  python /app/04_scripts/soybean_crop_progress/update_soybeans_crop_weekly.py
```

两个 `--env` 参数只包含变量名；Docker CLI 从宿主机包装脚本的当前环境取值。
命令参数、定时任务文本和日志中均不包含 Key 值，也不使用
`--env NASS_API_KEY=<值>`。变量只临时注入本次 `docker exec`，不写入容器永久配置。

服务器已于 2026-07-17 完成首次初始化及一次 `no_change` 复验。后续正常运行结果应为
`updated` 或 `no_change`，不应再次出现首次 `initialized`，除非稳定文件被受控移除。

## 拟定定时方式（本阶段不安装）

北京时间每周二、周三、周四 06:30 调用包装脚本。锁、密钥读取、提交解析和容器检查
全部由包装脚本负责，cron 不再直接拼接长 `docker exec` 命令：

```cron
30 6 * * 2-4 /usr/bin/bash /home/ubuntu/market-data/09_deploy/soybean_crop_progress/run_soybean_crop_weekly_update.sh >> /var/log/market-data-soybean-weekly-cron.log 2>&1
```

可选的 systemd timer 方案：

```ini
# /etc/systemd/system/market-data-soybean-weekly.service
[Unit]
Description=Market Data soybean weekly update

[Service]
Type=oneshot
ExecStart=/usr/bin/bash /home/ubuntu/market-data/09_deploy/soybean_crop_progress/run_soybean_crop_weekly_update.sh
```

```ini
# /etc/systemd/system/market-data-soybean-weekly.timer
[Unit]
Description=Run soybean weekly checks Tue-Thu at 06:30 Asia/Shanghai

[Timer]
OnCalendar=Tue,Wed,Thu *-*-* 06:30:00 Asia/Shanghai
Persistent=true

[Install]
WantedBy=timers.target
```

以上仅为后续上线方案。本地开发和验证不得读取服务器密钥、修改 crontab 或安装
systemd 单元。部署兼容修复并手工确认一次 `no_change` 后，才能安装定时任务。
