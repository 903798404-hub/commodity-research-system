# 进口商品利润研究框架契约

> 文档状态：当前项目唯一权威业务契约。本文定义通用框架、首期大豆实例以及历史与未来日度数据的真实价格口径；具体能力是否已经上线必须以当前代码、测试、运行 Release 和部署结果为准。

## 1. 项目范围与架构

- 通用框架名称：`进口商品利润研究框架`。
- 推荐 Python 包名：`import_profit`。
- 首个页面名称：`日度进口大豆盘面净榨利`。
- 后续品种：`进口菜籽压榨利润`、`棕榈油进口利润`。
- 大豆和菜籽使用压榨利润模型；棕榈油使用直接进口利润模型，不得套用出粕率或出油率。
- 三个品种只共享日期、空值、状态和审计字段等薄公共内核。每个品种保留独立计算器、参数、行情来源和合约映射，不建设复杂插件体系。

首期只锁定大豆可验证契约。本文件没有授权实现计算器、适配器、页面、更新任务或生产定时任务。

## 2. 大豆参数与产地

首期产地固定为：巴西、美湾、美西、阿根廷。四个产地共用以下默认参数：

| 参数 | 锁定值 | 单位或含义 |
|---|---:|---|
| 出粕率 | 0.795 | 吨豆粕/吨大豆 |
| 出油率 | 0.19 | 吨豆油/吨大豆 |
| 换算系数 | 0.367437 | 将美分/蒲式耳换算为美元/吨 |
| 关税率 | 0.03 | 比例 |
| 增值税率 | 0.09 | 比例 |
| 港杂费 | 50 | 元/吨 |
| 加工费 | 150 | 元/吨 |

配置保留按产地覆盖默认参数的结构，但首期 `origin_overrides` 必须为空，不得为尚不存在的差异填写虚构参数。

## 3. 计算口径

正式公式固定为：

```text
美元成本 = (CBOT日度价格 + CNF升贴水) × 0.367437

完税成本 = 美元成本 × 汇率 × (1 + 关税率) × (1 + 增值税率)

盘面净榨利 = 豆粕盘面 × 0.795
           + 豆油盘面 × 0.19
           - 完税成本
           - 港杂费
           - 加工费
```

首期不增加其他附加费用。页面只展示盘面净榨利；禁止展示盘面毛榨利、粕成本、油成本、豆粕盈亏平衡价、豆油盈亏平衡价。

## 4. CNF 数据契约

CNF 只表示进口大豆升贴水，单位为美分/蒲式耳。CNF 是当日主表唯一可编辑列，其他计算列只读。

稳定键按以下顺序固定：

```text
business_date
commodity
origin
shipment_year
shipment_month
```

可以派生 `shipment_period = YYYY-MM`，但不得用它替代稳定键完整性校验。同一稳定键再次保存时直接覆盖；允许补录和修改历史日期；不保存或展示业务修订历史。

CNF 空值必须保存为真实 `NULL`，数字 `0` 是有效平水报价。禁止向前填充、向后填充、跨日期继承、插值或以相邻船期替代。CNF 为 `NULL` 时，美元成本、完税成本和盘面净榨利均为 `NULL`。

## 5. 汇率契约

正式候选来源是 `01_data/manual/榨利表/油脂油料价格.sql` 中的 `美元兑人民币历史汇率`。汇率直接使用表中数值，不区分 Bid、Ask 或 Mid。

目标期限是从 `business_date` 所在年月到 `shipment_period` 所在年月的整数月差：

- 0 个月使用 `Spot`；
- 1 至 11 个月分别使用 `Fwd_1M` 至 `Fwd_11M`；
- 12 个月使用 `Fwd_1Y`；
- 负期限和大于 12 个月的期限均无效。

真实目标期限存在时必须直接使用。目标期限缺失时，只允许在同一 `business_date` 的相邻有效期限之间做线性插值；禁止跨日期插值和向 0 个月之前或 12 个月之后外推。插值结果必须保留 `is_interpolated`、`lower_tenor`、`upper_tenor`。

## 6. 业务日与缺失状态

近期表格和历史正式结果仍以 `Asia/Shanghai` 时区下的周一至周五为业务日主轴。周六、周日不进入日期轴；中国法定节假日即使落在周一至周五也保留历史日期行。该展示规则不代表大连商品交易所一定开市。未来08:30夜盘收盘冻结任务必须另行用可审计交易日历确认目标业务日期，不得仅按前一个自然日推断；当前最小实现使用 AkShare 可取得的中国交易日历，并明确记录其并非DCE专属日历的证据边界。

任一工作日缺少豆粕、豆油、CBOT、汇率或CNF时，日期行必须保留，对应字段和计算结果保持 `NULL`。不得因缺少行情自动删除工作日，不得使用上一业务日行情回填，也不得依据 AkShare 是否返回行情推断交易所开市或休市。页面和未来任务只展示客观数据状态，不猜测缺失原因；行情采集失败可以记录，但不得等同于休市。

## 8. 行情来源命名

CBOT 字段统一命名为 `CBOT日度价格`。在缺少新来源证据并正式更新契约前，不得称为“CBOT收盘价”或“CBOT结算价”。

历史豆粕和豆油价格继续使用已有数据库完成初始化和历史回算，底层 `price_type` 保持为 `historical_continuous_close`。不得重建历史数据、推断历史夜盘收盘价格，或把历史连续合约收盘价格改写为未来快照口径。

未来新增业务日期使用 AkShare `futures_zh_spot` 的指定完整 M/Y 合约价格，正式字段仅为 `current_price`，底层 `price_type` 固定为 `night_session_close`。该值的正式语义是“目标交易日对应的夜盘收盘基准”，不得描述为交易所官方结算价。页面继续使用“豆粕盘面”“豆油盘面”和“盘面净榨利”等简洁名称。

北京时间08:30任务须在半开区间 `08:30:00 <= captured_at < 08:33:00` 内运行。`captured_at` 必须为时区感知时间，转换为 `Asia/Shanghai` 后日期等于 `business_date`，且该日期必须存在于本次取得的交易日历中；这里的 `business_date` 同时是本次增量对应的目标 DCE 交易日，不是夜盘发生的自然日期。M/Y夜盘通常于23:00结束，其自然日期由交易日历中严格早于目标交易日的最近交易日确定，周一对应上周五，节后不得用 `calendar - 1 day` 推断。当前接口只提供行情时间、不提供可靠自然日期，因此只接受 `22:59:00 <= source_quote_time < 23:01:00` 的有限正数 `current_price`；接口若提供 `source_quote_date`，必须等于上述 expected night-session date。缺少行情日期或交易日历无法确定该日期时必须 fail closed，记录仅有时间证据，不得声称能够严格证明最后一笔的自然日归属。

目标合约继续由统一船期映射推导。一个业务日期的全部产地和船期应先合并为唯一完整合约集合，再以一次批量请求获取；不得按业务键重复请求或硬编码年份。0、负数、NaN、无穷、非法字符串、缺失合约和重复目标合约均不可使用。全部目标合约有效时状态为 `success`；至少一个有效但部分缺失或无效时为 `passed_with_incomplete`，只冻结有效合约并让依赖缺失合约的船期保持 `NULL`；核心接口、业务日期或行情时间校验失败，或没有任何有效合约时为 `failed`。批次身份保存在候选 Manifest 或质量报告中，不改变持久化 Schema。

未来日度数据组合固定为当日上午导入的 CBOT 日度价格与远期汇率、08:30冻结的国内夜盘收盘基准，以及用户随后录入的 CNF。同一业务日期的所有产地和船期统一使用已经冻结且各自可用的国内合约价格；录入、预览或保存 CNF 时不得重新获取行情。

历史数据和未来增量必须保留各自真实的 `source`、`source_function`、`source_quote_date`、`source_quote_time`、`captured_at`、`capture_timezone` 和 `price_type`，不得伪装为完全相同的原始来源。未来增量不得回退到前一日期、夜盘末值、最近成功值、下午价格、相邻合约、其他月份、历史连续收盘价、`close`、`settle`、`avg_price`、买卖价、昨收或昨结。快照失败时该业务日国内价格及相关榨利保持 `NULL`。AkShare 返回本身仍不得作为 DCE 开市或休市依据。

正式口径切换日期不是开发、提交或部署日期，而是服务器首次成功生成并提升包含 `night_session_close` 的业务日 Release 的 `business_date`，并由该日增量 Manifest 明确记录。切换日期之前的数据继续保持 `historical_continuous_close`；切换日期及之后的新业务日只允许 `night_session_close`。

## Phase A：事件驱动生命周期与持久 Readiness

Phase A 将 CNF 人工输入与机器生产职责拆开。研究员只提交真实 CNF；页面请求不得同步抓取行情、封存 Snapshot 或生成榨利。配置 `IMPORT_PROFIT_LIFECYCLE_STATE_ROOT` 后，页面保存只做两件事：继续写入既有 `manual_ui` operational CNF store，并向 AM、PM 两个独立 session 提交同一个 CNF envelope。未配置该路径时保留旧流程兼容性；Phase A 候选不修改部署配置、mount 或 grant，因此不能据此宣称生产已切换。

生命周期稳定键为 `business_date + commodity=soybean + session`。每个 session 的 durable state 原子保存在 `<lifecycle-root>/sessions/YYYY-MM-DD-AM|PM.json`，以 `state_revision` 做 compare-and-swap，并在同一文档保存连续 transition ledger、event identity、attempt evidence、blocking reason 与各输出 identity。CNF envelope 保存于 `<lifecycle-root>/cnf-submissions/YYYY-MM-DD/`，包含不可变 revision 和原子 `current.json`。其明确区分 `VALUE`、`NO_QUOTE` 与 `NOT_PROVIDED`；现有页面没有 NO_QUOTE 控件，所以页面空格只能记为 `NOT_PROVIDED`，不得冒充无报价。旧页面接入的 actor 固定标识为 `legacy-ui-unverified / legacy_ui_adapter`，直到独立 Human CNF Authorization identity 在后续阶段实现。

状态集合固定如下：

- Market：`NOT_READY → READY_TO_CAPTURE → CAPTURING → SEALED`，失败进入 `FAILED`，超过 session 合法窗口且没有合法 Snapshot 则进入 `MISSED_WINDOW`。
- CNF：`NOT_SUBMITTED → PARTIAL → SUBMITTED`。
- Profit：`WAITING_FOR_MARKET`、`WAITING_FOR_CNF`、`READY_TO_MATERIALIZE`、`MATERIALIZING`、`SEALED`、`FAILED`。

Market 与 CNF 事件顺序无关。只有 Market=`SEALED` 且 CNF=`SUBMITTED` 才能得到 Profit=`READY_TO_MATERIALIZE`。Phase A 不执行 materialization；它只产生可供后续独立 worker 消费的 durable readiness。CNF 写授权状态仅描述人工输入能力，不能阻断机器行情 capture。反之，CNF 缺失、部分提交或 Human Authorization 失效也不能成为 Market capture 的前置条件。

FULL DAILY 与 Soybean lifecycle 保持单向松耦合。FULL DAILY 的 `SUCCESS` 或 `PARTIAL_SUCCESS` 只允许产生完成事件，不能直接代表大豆行情已就绪。Readiness 必须按当前统一合约映射动态求出精确 CBOT 大豆、DCE 豆粕、DCE 豆油与 USD/CNH Spot identity，并逐组件验证存在性、身份和 freshness；天气、鲁投等非大豆组件失败不影响大豆判定。FULL DAILY 不等待 lifecycle，不读取 lifecycle state，也不因 lifecycle 失败而改变自身状态。

当前正式 capture 实现会通过 Tankan client 再次读取 live market tables，而不是消费 FULL DAILY 已冻结的同一不可变 source artifact。Phase A 保留这一真实来源行为，不虚构 source truth。若事件处理器没有具备授权的 machine capture callback，状态停在 `READY_TO_CAPTURE`，blocking reason 固定为 `MACHINE_IDENTITY_BLOCKER`，不得由研究员 grant 或浏览器身份代替。已有合法 immutable Snapshot 时，重启或重复事件必须从 Snapshot 收敛到 `SEALED` 且不得再次调用 provider；event idempotency key 和输出 identity 都必须确定性去重。

AM 合法窗口为北京时间 `[08:00, 12:00)`，PM 为 `[15:00, 21:00)`。窗口结束仍无合法 Snapshot 时只记录 `MISSED_WINDOW`，禁止补抓、伪造或把之后行情写成该 session。2026-09-24 事故只作为测试 fixture，用来证明过期人工授权、空 CNF 与 AM missed window 可以同时存在，且系统不会回填当日生产数据。

Lifecycle root 的正式路径固定为 `/runtime/import-profit/operational/lifecycle`。任何写入都必须同时通过 runtime machine identity 的精确路径和 writable-root 校验；Phase A 不创建或扩展 grant。页面仅只读展示当日 AM/PM 的 Market、CNF、Profit 和 blocking reason，不承担调度、重试或告警。正式 machine service identity、事件投递/定时兜底、materialization worker、指数退避与告警属于后续阶段和独立生产门禁。
