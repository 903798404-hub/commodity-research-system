# Windows FULL DAILY 无人值守 Wrapper

本 Wrapper 解决 Windows 本地进程的环境、互斥、证据和超时治理；唯一业务入口仍是
`04_scripts/refresh_public_data.py`，Wrapper 不选择 provider，也不复制刷新规则。

固定调用方式：

```powershell
& 'C:\Users\xx202\Desktop\codex自动更新\codex-projects\market-data\04_scripts\automation\run_full_daily_windows.ps1' -TriggerSource manual
```

未来 Codex Automation 使用同一命令，仅把 `manual` 改为 `scheduled`。触发来源只进入审计字段，
不改变业务命令。电脑关机时不会产生 Run；开机后可手动产生一个新 Run。同一天可顺序运行多次，
但外部 OS 文件锁禁止并发。

运行前须由当前 Windows 用户提供以下 User-level 非敏感环境变量：

- `MARKET_DATA_SSH_TARGET`
- `MARKET_DATA_REMOTE_STORE_ROOT`
- `MARKET_DATA_ACTIVATION_IMAGE_ID`（不可变 `sha256:` Image ID）
- `MARKET_DATA_FULL_DAILY_PRODUCTION_COMMIT`（显式批准的完整 Git commit SHA）

固定 PowerShell launcher 不再从调用者当前目录或 `$PSScriptRoot` 推导业务 checkout，也不执行 local main
工作树中的 bootstrap 文件。它使用唯一批准来源 `MARKET_DATA_FULL_DAILY_PRODUCTION_COMMIT` 从对应 Git
object 临时物化 stdlib bootstrap；bootstrap 在线读取并 fetch `origin/main`（只更新 remote metadata），
验证批准 commit 存在且属于可信 main 历史，计算批准 tree，然后创建 clean detached 控制面 checkout。
远端不可用时 fail closed，不使用可能过期的 remote-tracking ref 猜测身份。

正式 Wrapper 从该批准控制面 checkout 加载；它再次核验可信远端身份，再为本轮创建独立的 clean
detached `tool-repo`。正式业务入口 `04_scripts/refresh_public_data.py`、Python imports、cwd、weather
baseline/config 路径均来自该 `tool-repo`。子 Python 使用 `-I`，并移除 `PYTHONPATH`、`PYTHONHOME`，
所以当前打开的 main、feature、integration、detached 或 dirty 开发 checkout 不参与 production code
identity。`repository_main_head/tree` 审计字段现在表示本轮在线确认的可信远端 main，而不是调用者 HEAD；
`repository_branch` 固定为 `NOT_APPLICABLE`。

提升生产身份仍只能由人工显式更新上述 User-level 环境变量，不能自动跟随 main。首次启用本架构时，
批准 SHA 必须指向已经包含本 bootstrap/approved-entry 合同的正式 commit；合入前的旧批准 SHA 不兼容
新增的控制面握手参数，因此本候选阶段不得用于真实生产运行。

Wrapper 通过严格非交互 SCP 按服务器 `current.json` 指向的不可变 package_id 只读下载本轮基线，
随后用现有 Production Package 校验器验证；不依赖人工维护的历史 acceptance cache。

数据库凭证继续只从 `%USERPROFILE%\.market-data-secrets\tankan.env` 和 `lutou.env` 读取。

正式运行证据位于当前 Windows 用户的
`%LOCALAPPDATA%\market-data-runtime\automation`：
每个 Run 有 `invocation.json`、`preflight.json`、`run.log`、`process-exit-code.txt`、
`final-status.json`、`runtime\`、`tool-repo\`。`current-status.json` 表示最近一次已完成运行；
`last-success.json` 只在成功时更新。只有进程退出码和 Daily Manifest 全部满足合同才封为
`SUCCESS`；否则为 `FAILED` 和稳定 `failed_stage`。锁冲突单独为 `SKIPPED_ALREADY_RUNNING`。
`invocation.json` 与最终状态同时记录 `repository_main_head`、`repository_main_tree`、
`production_commit`、`production_tree` 和 `trigger_source`。

Wrapper 在创建 Run 前执行 `RUNTIME_FILESYSTEM` 硬闸门：正式 runtime 必须精确位于
LocalAppData，不得在仓库、Desktop、Documents 或 OneDrive 等同步目录中，且目标及
关键父目录不得带 `IO_REPARSE_TAG_CLOUD_*`。发现 Cloud Files 时 fail-closed，不执行
provider 或 FULL DAILY。旧 `market-data-worktree-runtime\automation` 只保留为历史审计证据，
Wrapper 不迁移、覆盖或删除其内容。
